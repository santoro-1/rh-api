# 语义视觉素材库与智能编排开发文档

> 文档状态：阶段 0～8、catalog v3 人工审核与本地迁移已实施；真实成片节奏仍需人工抽样
> 文档版本：v1.4
> 更新时间：2026-08-13
> 关联项目：云端数字人网站 `runninghub_mvp`、本地剪映工作台 `jyd_plain_json_probe`

本文档是语义前景图片、语义前景视频、相关素材和空镜自动编排的开发依据。低层
catalog、asset、recipe 和相对路径协议继续以《语义视觉素材统一协议设计》为准；如果两份
文档在大模型调用次数、返回字段或调度规则上存在冲突，以本文档为准。

2026-08-13 起，本文档中的时间、去重、空镜密度和接缝规则以第 8 节及第 15 节的
`sentence-v1` 当前值为准；阶段实施记录中保留的旧参数只用于历史追溯。未经明确授权，不部署
生产环境，不修改云端账号数据库。

## 1. 已确认的产品结论

1. 每份脚本的智能内容分析只调用一次大模型。
2. 一次调用同时完成音乐意图、字幕语义断点和语义视觉计划。
3. 完整脚本只发送一次，不向大模型发送 MiniMax 时间戳。
4. 字幕和语义视觉共用同一套语义边界，不让模型重复切句。
5. 大模型只返回精简决策，不返回时间、文件、媒体轨道、位置、尺寸、持续时间或解释文本。
6. 图片和视频是同一种 `semantic visual asset` 的不同媒体类型，共用一份视觉计划和一条
   时间占用通道；同一时间不能同时自动显示语义图片和语义视频。
7. 明确语义素材优先，相关素材和空镜只用于填补较长视觉空窗；没有高相关素材时不强行添加。
   编辑型泛氛围素材只用于数字人片段接缝，每个接缝最多一条、以边界为中心显示约 1 秒；只有
   与接缝前后具体对象、动作或明确生活场景高度相关且 `priority=2` 时自动使用，不增加淡入淡出。
8. 图片位置以真实剪映结果为准，浏览器预览复用同一几何换算。下方素材的最高优先级是不遮挡人物。
9. 字幕、固定人名牌和语义视觉是不同轨道。下方贴图保持在人名牌下方；全屏 B-roll 轨道
   固定在人名牌上方、字幕下方，通过层级自然覆盖人名牌，不增加显隐状态逻辑。
10. 实现必须保留单项失败隔离、人工编辑和人工锁定能力。
11. 网络素材使用 `rights_status=attributed`：素材实际显示期间必须在右上角显示“素材来源于网络”，
    字体、字号、颜色、透明度、缩放和阴影复用底部固定免责声明参数。

  - 相同 concept 至少间隔 20 秒；
  - 相同 asset 在整条成片内最多自动使用一次；
  - 已选素材不能互相重叠。
- 2026-08-13 完成 210 素材人工审核与迁移：209 个入库（206 自动、3 仅手动），1 个移除；

## 3. 目标总流程

```text
完整脚本
    ↓
本地生成安全断点编号、视觉锚点编号和紧凑 concept 候选
    ↓
一次大模型调用
    ├── music_intent
    ├── subtitle_breaks
    └── visual_plan
            ↓
服务端分别校验三个分支并写入统一分析缓存
            ↓
本地使用 subtitle_units + MiniMax raw_cues 绑定真实时间
            ↓
本地选择具体图片或视频
            ↓
统一调度明确语义素材、相关素材和空镜
            ↓
浏览器审核和人工锁定
            ↓
生成剪映图片/视频轨道
```

## 4. 单次大模型调用设计

### 4.1 调用边界

继续扩展现有 `content_analysis` 调用，不再新增第三套分析服务。一次 provider 请求必须读取完整
脚本并完成三个分支：

1. `music_intent`：保持现有音乐意图能力。
2. `subtitle_breaks`：保持现有单行字幕自然断点能力。
3. `visual_plan`：返回值得进入本地调度器的语义视觉计划。

单次调用不等于三个分支必须共用失败状态。服务端仍按分支解析和保存：视觉分支校验失败时，
已经有效的音乐和字幕结果仍可使用；音乐或字幕分支失败时，也不得删除已经验证的视觉分支。

### 4.2 provider 输入

provider 输入保留：

- `original_script`：完整原始脚本，只发送一次。
- `boundary_indexed_script`：现有字幕安全断点编号文本。
- `visual_concepts`：本次脚本可选择的紧凑 concept 列表。
- `visual_anchors`：可用于视觉出现位置的短编号；不包含时间戳。

不发送：

- MiniMax `raw_cues`；
- 字幕或视觉时间戳；
- 本地绝对路径；
- asset 文件名和完整素材清单；
- 浏览器和剪映布局参数；
- 当前轨道 JSON。

`visual_concepts` 只包含 `concept_id`、短标签和一句短说明。素材量较小时可以发送全部可用 concept；
当 concept 数量超过约定阈值后，先用 aliases、标签或本地召回缩小到 top-k。召回只负责缩小允许集合，
不代替大模型做语境判断，也不增加模型调用次数。

### 4.3 字幕断点与视觉锚点共用边界系统

不再让视觉模型重新切句。现有安全边界编号同时服务字幕与视觉：

- `subtitle_breaks` 选择哪些边界适合作为单行字幕断点；
- `visual_plan.anchor_id` 选择语义画面应绑定到哪个原文边界；
- 服务端把边界编号映射回稳定的 Python 字符范围；
- 本地再通过 MiniMax `raw_cues` 映射真实时间。

视觉锚点必须引用输入中实际存在的编号。脚本开头需要提供专用 `START` 锚点，但本地开场保护仍可
把实际显示时间后移或直接舍弃该视觉项。

字幕最终屏显块不能直接充当视觉候选。字幕可能因 13 字单行限制被拆得很细；视觉应使用相邻字幕
单元合并后的完整语义组，避免一句话产生多张图。

### 4.4 provider 精简输出

provider 根对象只保留三个业务分支，不要求模型复述脚本哈希、catalog 版本和 Prompt 版本：

```json
{
  "music_intent": {},
  "subtitle_breaks": {
    "prefer_after": [6],
    "allow_after": [13]
  },
  "visual_plan": [
    {
      "anchor_id": "B18",
      "concept_id": "food.cucumber",
      "priority": 2
    },
    {
      "anchor_id": "B52",
      "concept_id": "activity.walking",
      "priority": 1
    }
  ]
}
```

每条 `visual_plan` 只有三个字段：

| 字段 | 说明 |
|---|---|
| `anchor_id` | 输入中的短锚点编号，定位原文位置，不是时间戳 |
| `concept_id` | 必须来自本次允许的 concept 集合 |
| `priority` | `0/1/2`，用于本地冲突选择；2 为关键，1 为普通，0 为仅供人工审核 |

模型只返回值得考虑的视觉项，未返回即视为 `SKIP`。不再为每个候选逐条返回 `SHOW/SKIP`。
`usage` 和短语 `context` 只存在于输入锚点，不进入模型输出：`explicit` 表示原文直接命中，
`enrichment` 表示可为空的空窗候选。enrichment 只有高度相关且返回 `priority=2` 才允许本地
自动使用，`priority=0/1` 均保留为审核项，不能为了填充画面强行进入成片。

模型不得返回：

- `confidence`；
- `importance`；
- `usage`；
- `reason_code` 或自然语言 reason；
- `asset_id`、`media_type`、路径；
- `start_us`、`duration_us`；
- 位置、尺寸、透明度和动画；
- `script_sha256`、`catalog_version`、`schema_version`。

### 4.5 元数据由服务器填写

工作台接口仍需要以下元数据，但全部由服务器从请求、配置和缓存键中填写，不占用模型输出 token：

- API `schema_version`；
- `script_sha256`；
- `catalog_version`；
- `prompt_version`；
- 模型名称；
- provider request id；
- cache hit 和分支状态。

缓存键至少包含用户、脚本摘要、catalog 版本、统一 provider schema、Prompt 版本和模型。catalog 变化时
需要重新获得视觉计划；旧的字幕和音乐结果是否复用属于内部优化，不得因此增加同一次用户操作中的
模型调用次数。

## 5. 大模型视觉判断规则

大模型只负责回答：当前语义位置是否值得出现视觉素材，以及最匹配哪个 concept。

按以下优先级产生 `visual_plan`：

1. 明确且有帮助的实物、食物、动作和过程。
2. 能显著帮助理解当前句子的相关场景。
3. 长段口播中与当前主题高度相关的空镜。
4. 仅仅为了让画面变化、但语义相关度不足的素材不返回。

必须跳过：

- 成语、比喻、否定、讨论词语本身；
- 一带而过且对理解没有帮助的名词；
- 与当前句子只有宽泛主题关系的万能空镜；
- 同一句中价值更低的重复概念；
- 无法从允许 concept 中准确表达的画面。

模型不决定图片还是视频。动作、过程优先视频，静态物品优先图片等策略由 catalog 标签和本地素材
选择器执行，避免扩大 provider 输出。

## 6. 本地时间绑定

大模型返回锚点后，本地执行：

```text
anchor_id
    ↓
原文字符位置或语义组
    ↓
subtitle_units
    ↓
MiniMax raw_cues
    ↓
start_us / duration_us
```

MiniMax 时间戳是时间事实的唯一输入。大模型不生成、不校正也不复述时间戳。

开场规则：

- 固定人名牌、字幕和自动语义视觉都允许从第 0 秒开始；
- 第一条自动语义视觉仍必须命中有效关键词或模型确认的语义锚点；
- 自动项不得为了避让开场而延迟，必须从关键词所在句段的发音开始显示；
- 普通句显示到句段结束，不足 2 秒时延长到 2 秒且不越过成片末尾；
- 顿号列举共同覆盖整个句段，按关键词语音中心点确定切点，单项不要求 2 秒。

## 7. 素材选择规则

### 7.1 统一素材选择

`concept_id` 确定后，本地从 catalog 中选择具体 asset：

1. 过滤不可用或资源缺失的资产。
2. 按 concept 匹配图片和视频。
3. 静态食物、单一物品和信息图优先图片。
4. 运动动作、烹饪过程和变化过程优先视频。
5. 首选媒体缺失时允许回退另一媒体。
6. 先把已启用手工锁定项登记到成片级 `used_asset_ids`；同一 concept 多个 asset 采用稳定轮换。
7. 首选已用、资源失效或用途不符时继续尝试下一个候选；全部用尽则跳过，不复用兜底。
8. 选择结果冻结到 recipe，后续 catalog 变化不能静默替换人工锁定项。

### 7.2 不建立独立视频配方

图片和视频继续共用：

```text
visual_analysis.visual_overlays[]
```

只通过 `media_type=image/video` 和 renderer 分发。不得新增一套与图片互不知情的
`semantic_video_overlays`，否则无法可靠处理冲突、密度和人工锁定。

## 8. 统一时间轴调度规则

所有自动图片和视频进入同一个语义视觉占用表。字幕和固定人名牌不进入该互斥表。

### 8.1 硬规则

1. 同一时间最多一个自动语义视觉素材。
2. 图片与视频重叠时只能保留一个。
3. 已锁定的人工素材优先于任何自动素材。
4. 相邻标点分句不增加固定开始间隔，但时间区间不得重叠。
5. 60 秒内自动语义视觉总数最多 24 条；相关素材不能绕过总上限。
6. 相同 concept 在 `semantic_overlay/full_screen_broll` 同一展示角色内至少间隔 20 秒。
7. 相同 asset 在整条成片的自动 overlays 中最多出现一次。
8. 占位优先级依次为人工锁定、数字人接缝空镜、通用 enrichment、明确语义。
9. 冲突时按 `priority`、importance、confidence 和脚本顺序确定保留项。
10. 边缘重叠不超过 0.5 秒时允许裁短或顺延新素材；更大重叠仍舍弃低优先级项。

### 8.2 明确语义与丰富性规则

本地先为全屏相关素材预留时间，再安排明确语义小窗：

1. 明确 aliases 命中且模型选择对应 concept 的项标记为 `explicit`。
2. 没有直接命中但模型选择了相关 concept 的项标记为 `enrichment`。
3. 普通 enrichment 目标间实际至少间隔 6 秒。
4. enrichment 每分钟最多 4 条，并受总数最多 24 条约束；候选锚点每 50 字一个、单条最多 12 个。
   单 anchor 最多 8 个概念，连续 anchor 轮换分发全部获准概念，保持云端紧凑合同。
5. 没有合格 enrichment 时保持数字人口播，不强行填充空镜。

这里的“空窗检测”只是对已选素材时间区间做确定性计算，不是第二次大模型调用，也不是本地语义模型。

## 9. 画面位置和呈现方式

### 9.1 下方前景图片或小窗视频

- 以剪映实际效果作为验收标准。
- 默认使用 `bottom_center` 锚定画面下方并与画面中轴对齐；食物图可以横向铺开下半区，动作
  小窗保持比食物图略窄。
- 核心约束是素材上边缘不能过高、不能遮挡人物脸部和主要上半身。
- 第一版使用数字人模板固定安全区，不增加人脸或人物检测模型。
- 不用一个固定 scale 套用所有宽高比；按素材尺寸计算最终可见高度。较高素材允许底边裁出，
  以保持足够宽度，同时限制上边缘不超过约 37% 的下方区域。
- 浏览器预览的换算必须通过真实剪映样本标定，不能只依赖代码中的理论比例。

### 9.2 全屏相关视频或空镜

- 暂时覆盖数字人基础画面。
- 字幕继续显示。
- 固定轨道层级为 `数字人底画面 < 固定人名牌 < 全屏 B-roll < 字幕`；B-roll 通过遮盖自然
  不显示人名牌，结束后底层人名牌自然可见，不生成隐藏/恢复事件。
- B-roll 原音默认静音，不能破坏主口播、BGM 和语音。

呈现方式来自 asset 默认配置或本地规则，不增加大模型返回字段。

## 10. 代码结构约束

为了避免形成两套并行链路或继续扩大单文件，实施时必须遵守：

1. 云端只保留一个面向当前项目的 provider 调用入口。
2. 现有 `content_analysis` 负责统一 Prompt、provider schema、单次调用和分支解析。
3. 旧 `visual_analysis` 服务在迁移期只做兼容读取或转发，不再独立调用模型；迁移完成后移除死代码。
4. 字幕边界编号、视觉锚点编号和字符位置映射共用一个实现，不复制字符对齐算法。
5. 本地 catalog、素材选择、时间绑定和调度保持纯函数边界，分别可单元测试。
6. 视频与图片共用 recipe 和冲突检查，只在 renderer 层分支。
7. 业务阈值集中定义并带名称，不在前端、云端和本地多处散落 `6_000_000` 等魔法数字。

## 13. 兼容、失败与回滚

- 旧 `visual_analysis` 结果和 recipe 继续可读，不能因新契约导致历史项目无法渲染。
- 新统一分析失败时，项目仍可使用旧的有效冻结配方；没有旧配方时安全跳过视觉增强。
- 字幕或视觉任一分支失败，不得破坏原始脚本、语音和基础视频。
- provider schema、Prompt 和 catalog 版本必须进入缓存键。
- 不原地覆盖已发布素材文件；新增版本使用新的 asset_id 或资源目录。
- 第一版不删除旧接口和数据库字段；先停止新写入并验证兼容读取，再安排清理。

## 15. 已确认的默认参数

以下默认值已经确认并作为实现约束：

1. provider `visual_plan` 采用“只返回选中项”，未返回即 SKIP。
2. 单条视觉计划只返回 `anchor_id + concept_id + priority` 三个字段。
3. `priority=0` 只进入人工审核；普通明确语义允许 `1/2` 参与自动调度，enrichment 与
   `seam_broll` 只有 `priority=2` 自动使用，`priority=1` 仅供审核。
4. 自动语义视觉总上限为每 60 秒 24 条；普通项从句段开头显示，除片尾外最短 2 秒。
5. 顿号短列举共同覆盖整个句段并按语音顺序速切，单项不做 2 秒保底。
6. enrichment 实际至少间隔 6 秒，每 60 秒最多 4 条；候选节奏由 10 秒常量控制。
7. 第一条语义视觉允许从第 0 秒开始；同 asset 成片级自动去重，同 concept 按展示角色保留 20 秒密度冷却。
8. 数字人分段接缝只使用与前后具体对象、动作或明确生活场景高度相关的获准 `seam_broll`；
   每个接缝最多一条，以边界为中心显示约 1 秒，没有高相关素材时保留原拼接与溶解。
9. 视频目标时间长于源片可用区间时，仅在该次 overlay 内静音循环并裁齐。
10. 全屏 B-roll 固定在人名牌上方、字幕下方，不实现人名牌显隐状态切换。
11. 图片和小窗视频默认使用画面下方人物安全区并沿中轴对齐；食物图默认宽度 78%，动作窗默认
   宽度 61.5%，高素材最多显示下方约 37% 并允许底边裁出，以真实剪映显示为准。

## 16. 待实施：中文文件夹驱动的贴图自动映射

> 记录日期：2026-08-24  
> 状态：方案已确认，尚未实施，不改变当前 `catalog.json` 运行链路。

目标是让素材维护者只管理中文目录和图片，不再手工编辑大型 Catalog。现有关键词召回、统一
内容分析、时间绑定、去重、冻结配方和剪映渲染继续复用；在 Catalog 前新增“目录扫描与自动
注册”层。

建议第一阶段只支持图片贴图，目录约定如下：

```text
semantic_visual_library/
  source/
    苹果/
      01.png
      02.jpg
    蒸苹果/
      01.png
    苹果型身材/
      01.png
  generated/                 # 程序生成，用户不直接维护
  semantic_visual_index.db   # 文件夹、别名和稳定素材 ID
```

实施边界：

1. 新增文件夹扫描器，识别 PNG/JPG/WEBP，计算 SHA-256，并拒绝损坏文件、空目录和越界路径。
2. 使用独立 SQLite 索引保存 concept、aliases、asset、相对路径、文件摘要、启停状态和生成包路径；
   文件夹名只作为默认 label/alias，不能直接充当永久 `concept_id` 或 `asset_id`。
3. 首次登记后生成永久稳定 ID；移动同内容文件时通过摘要复用原 asset ID，目录改名不得使历史
   项目失去原 concept ID。
4. 将普通图片自动包装成现有渲染器兼容的
   `generated/bundles/<asset_id>/sticker.json + resources/sticker/singleImage.png`，避免修改历史
   `jyd_sticker_bundle` 配方和剪映渲染协议。
5. 加载时合并现有 catalog v3 与文件夹索引素材；现有 1454 个正式素材及历史 asset ID 保持不变。
6. 增加管理接口和“贴图素材库”页面，支持扫描、预览、设置同义词、启停和查看新增/失效/重复
   状态。扫描结果必须先完整校验再原子切换，失败继续使用上一版可用索引。
7. 普通匹配仍采用长词优先和整句模型复核；例如“苹果鸡蛋汤”优先于“苹果”，“苹果手机”不因
   目录名命中而自动插入水果图。
8. 删除源文件只停止新任务选用，不立即删除生成包；物理清理前必须审计历史冻结配方引用。
9. 整机迁移时整体复制 `semantic_visual_library`，其中同时包含 source、generated 和索引数据库。
10. 视频目录扫描、FFprobe、用途分类、干净窗口和版权审核留到第二阶段，不能套用图片默认值自动
    开放全屏或接缝空镜。

## 17. 数字人连接处空镜弱匹配审计（2026-08-24）

### 2026-08-31 对第 16 节方案的本地测试实施修订

按用户后续确认，文件夹图库本轮同时包含图片和视频；测试环境使用 `folders` 单一来源，
不执行第 16 节原计划中的“合并旧 catalog”，也不自动回退旧 JSON。正式默认模式不变。
已有 catalog 只在显式 `semantic_visual_folders migrate` 时读取一次，复制原素材并保存
concept/asset ID、别名、视频已审范围、用途、版权署名和禁用记录到 SQLite。原 JSON/目录保留。

素材目录使用 `素材/大类/小类/图片或视频`；大类仅组织，小类用于具体词匹配。普通图片生成
既有 `jyd_sticker_bundle` 兼容包，视频生成不可变本地缓存；新增视频默认最多 3 秒静音小窗，
不会因此获准全屏或接缝用途。旧视频的审核权限和弱匹配限制不变。

索引按需增量扫描、事务发布，损坏或复制中的文件暂不启用。初次按行级种子随机选材，recipe
保留种子和已选素材；跨目录按内容摘要去重。删除/改名源文件不清理历史缓存，不因图库切换
批量重写历史配方。当前范围不增加管理页面；后续 UI、别名管理和视频审批界面另行讨论。
实现和操作文档在 JYD 的 `src/jyd_probe/semantic_visual_folders.py`、
`docs/SEMANTIC_VISUAL_LIBRARY.md`，未修改云端接口、账号库或部署生产。

当前自动连接处空镜已经关闭弱匹配和本地氛围兜底，必须同时满足：

1. concept 来自接缝前后脚本直接召回的具体对象、动作或明确场景，`editorial.*` 不进入统一模型
   的允许 concept 集合；
2. 模型对该直接 concept 返回 `priority=2`；`priority=0/1` 只保留审核，不自动使用；
3. 本地选材要求该视频自身的 `concept_ids` 精确包含所选 concept，并声明 `seam_broll`，使用
   `match_tier="exact"`；分类 fallback、唯一素材和编辑型池均不能兜底；
4. 没有模型批准的强匹配、没有未用的精确素材或发生时间冲突时，保持原数字人接缝与溶解，不
   自动插入空镜。

兼容代码仍可能在候选构建阶段整理编辑型池，但请求过滤、决策门槛和最终精确选材三层都会阻止
其自动进入成片；后续重构可以删除这段无效候选构建，以减少误读，但不得放宽上述运行边界。
