# 食物语义贴图功能快速接入开发文档

> 文档版本：MVP 立即接入版
> 更新时间：2026-08-08
> 目标：先把一批高频食物贴图接入现有语义贴图功能，尽快做到可分析、可预览、可人工修改、可生成剪映草稿。

> 底层 catalog、recipe 和图片/视频统一资产协议以《语义视觉素材统一协议设计》为准。2026-08-08 已完成 catalog v2 迁移：原有 7 个素材与新增 12 个食物素材已正式接入，共 18 个概念、19 个图片素材。

## 1. 当前第一目标

本阶段不先开发完整素材库管理系统，也不先解决素材添加、删除、停用、历史审计、跨机器迁移工具或全局批量控制。

当前唯一主目标是：

> 从 `D:\迅雷下载\贴图素材-巧如` 中选出一批与现有脚本高频食物概念匹配的图片，将其转换成当前功能已经支持的剪映 sticker bundle，加入现有 `catalog.json`，让用户立即可以在项目中进行语义分析、预览、单条修改和剪映草稿生成。

本阶段完成后，应当可以直接在当前前端中使用新食物贴图，不等待素材库后台、批量管理页面或新渲染协议。

## 2. 本阶段明确不做

为了缩短上线时间，本阶段暂不做：

- 人物、明星、裴老师、真人身体和减肥前后对比素材。
- 普通 PNG/JPG 直接渲染协议。
- 素材库添加、删除、停用后台。
- catalog v2 或 `enabled` 字段。
- 跨全部历史项目的引用审计和安全删除。
- 完整素材库搬迁工具。
- 项目级全部贴图一键开关和批量样式修改。
- 项目级大模型微批或整项目单次调用改造。
- FunASR 精确时间接入语义贴图。
- 生产环境部署。

这些内容全部放到 MVP 可用之后继续开发，不阻塞当前接入。

## 3. 直接复用现有功能

现有链路已经具备本次 MVP 所需能力：

1. 本地根据 catalog aliases 召回候选。
2. 没有候选的脚本不调用云端模型。
3. 云端模型只能在 `allowed_concepts` 中选择。
4. 模型返回 SHOW/HIDE、concept、confidence、importance 和原因。
5. 低于置信度阈值的结果不自动展示。
6. 浏览器预览读取冻结后的 `visual_overlays`。
7. 用户可逐条加入、移除、换图、改位置、缩放、透明度和时间。
8. 本地 4B 剪映草稿读取同一份冻结配方。
9. 单张贴图失败不会破坏字幕、BGM、语音或基础视频。

因此，本阶段尽量不改云端接口、不改前端交互、不改 recipe schema，也不扩展渲染器。

最短实现路径只有两项核心工作：

1. 把选中的普通图片转换为当前可以渲染的标准 sticker bundle。
2. 把新 concept 和 asset 添加到现有 catalog。

## 6. 图片处理规则

本阶段不做复杂的自动抠图系统。为了最快可用，采用“照片卡片/信息图卡片”方式。

### 6.1 统一输出

每张素材生成：

```text
1254 × 1254 PNG，sRGB
```

输出文件固定为：

```text
resources/sticker/singleImage.png
```

### 6.2 普通食物照片

适用于坚果、牛奶、鱼、虾、牛肉、鸡胸肉、豆腐、黄瓜、水果和早餐。

处理方式：

1. 按主体居中裁剪为正方形。
2. 不拉伸图片。
3. 主体尽量占画面 65%～90%。
4. 输出到 1254 × 1254。
5. 第一版允许保留照片背景，不等待透明抠图。
6. 如果裁剪后主体丢失，改用等比缩放加统一浅色背景。

### 6.3 信息图卡片

适用于蛋白质食物和优质碳水。

处理方式：

1. 保持整张信息图比例，不裁掉文字。
2. 等比缩放到 1254 × 1254 画布内。
3. 空白区域使用白色或与原图一致的浅色背景。
4. 默认 scale 使用 0.23，避免遮挡数字人和字幕。

### 6.4 MVP 使用限制

- 技术接入不因图片没有透明背景而阻塞。
- 带平台水印的素材可以用于本地功能验证；如果视频需要正式发布，应换成确认可用的干净源图。
- 不处理人物照片。
- 不自动删除或覆盖原始下载素材。

## 7. 需要新增的批量生成脚本

在本地工作台项目中新增一个简单的离线脚本：

```text
tools/library/build_food_semantic_bundles.py
```

脚本只负责当前 MVP，不先建设通用素材管理平台。

### 7.1 脚本输入

建议在脚本中维护一份明确的首批配置：

```python
FOOD_ASSETS = [
    {
        "concept_id": "food.nuts",
        "asset_id": "nuts.mixed.01",
        "source": "蛋白质/坚果.webp",
        "bundle": "nuts_mixed_01",
        "fit": "cover"
    }
]
```

源素材根目录通过命令行参数传入，不写死盘符：

```text
python tools/library/build_food_semantic_bundles.py --source-root <新素材目录> --output-root <staging目录>
```

### 7.2 脚本行为

1. 检查源文件存在并可以解码。
2. 按 `cover` 或 `contain` 规则生成 1254 × 1254 PNG。
3. 从已验证模板复制完整 bundle。
4. 替换复制后 bundle 中的 `singleImage.png`。
5. 计算输出文件 SHA-256。
6. 输出 `catalog.patch.json` 或可供人工合并的新增 concepts/assets JSON。
7. 输出生成报告，列明成功、失败和目标路径。

### 7.3 安全要求

- 输出只能写入新的 staging 目录。
- 如果目标 bundle 已存在，直接报错，不覆盖。
- 不修改正式 catalog。
- 不修改原始图片。
- 任意单张失败时继续处理其他图片，最终返回部分失败报告。

## 8. catalog 修改内容

生成成功并目检后，人工将新增 concept 和 asset 合入：

```text
data/libraries/semantic_visual_library/catalog.json
```

每个 concept 使用现有字段：

```json
{
  "concept_id": "food.nuts",
  "label": "坚果",
  "description": "作为食物、加餐或明确营养搭配出现的坚果",
  "aliases": ["混合坚果", "巴旦木", "坚果", "核桃", "杏仁"]
}
```

每个 asset 使用现有字段：

```json
{
  "asset_id": "nuts.mixed.01",
  "concept_id": "food.nuts",
  "name": "混合坚果",
  "bundle": "bundles/nuts_mixed_01",
  "image": "bundles/nuts_mixed_01/resources/sticker/singleImage.png",
  "default_corner": "top_right",
  "default_scale": 0.26,
  "default_opacity": 1.0
}
```

注意：

- aliases 应按较长、较具体的词优先排列。
- `protein` 不使用单独的“蛋白”作为 alias，避免把“蛋白”误判成鸡蛋清。
- `milk` 不使用单独的“奶”，避免召回酸奶、奶茶等无关语境。
- `fish` 不把“鱼油”加入 alias。
- bundle 和 image 必须使用相对路径。

补充测试：

### 步骤 6：前端实际验证

4. 图片能在浏览器预览中显示。

### 步骤 7：生成一个真实本地剪映草稿

1. 选择至少包含 3 张不同食物贴图的项目。

4. 检查显示时间、位置和尺寸。
5. 人为制造一张无效贴图，确认其他贴图、字幕、BGM、语音和基础视频仍能生成。

完成标志：新食物贴图在真实剪映草稿中可见，且失败隔离仍有效。

### 步骤 8：运行云端协议回归测试

## 10. MVP 验收标准
