# 剪映自动化生成项目

开发、调试、扩展和打包请先阅读 [开发者指南](docs/DEVELOPER_GUIDE.md)。普通安装与使用从 [START_HERE.md](START_HERE.md) 开始。本轮数字人账号与任务收件箱改造见 [数字人任务接入变更记录](docs/DIGITAL_HUMAN_INTEGRATION_20260803.md)。

这是一个自包含的剪映草稿采集、素材管理、批量生成和处理机服务项目。源码、前端、母版、素材库以及 `jy-draftc` 解密程序都已经放进本项目目录；构建缓存放在项目外，因此整个 `jyd_plain_json_probe` 文件夹可以直接压缩并迁移。

> 当前渲染链路依赖 Windows 剪映客户端和 Windows UI 自动化。中央网站可以独立部署，但实际导出的 Agent 必须运行在安装了剪映且桌面会话保持可用的 Windows 电脑上。

运行日志按组件持久化并自动轮转：Processor 使用 `data/logs/workbench.log`，本地渲染使用
`data/logs/render.log`，内嵌 Collector 使用 `data/logs/collector.log`；独立 Agent 使用
`%LOCALAPPDATA%/JianyingRenderAgent/logs/agent.log`。默认单文件 10 MB、保留 14 天，凭据在
写入前脱敏。

新版工作台顶部“运行记录”只展示当前项目的重要步骤和状态；需要协助排查时，可从同一窗口
下载仅限当前项目的脱敏诊断包。诊断包不会包含完整脚本、素材文件或路径、操作负载和登录凭据。

## 最常用的四个入口

```powershell
# 启动处理机网站（新版工作台默认 http://127.0.0.1:8010/app/new）
.\start_processor.ps1 -ProcessingMode standalone

# 启动本机草稿读取/上传工具（后台运行，不需要打开独立页面）
.\start_collector.ps1

# 启动隔离的测试网站与测试采集器（分别在两个 PowerShell 窗口运行）
.\start_test_processor.ps1
.\start_test_collector.ps1
# 测试页面：http://127.0.0.1:8001/app

# 多处理机模式：中央服务与独立处理机 Agent
.\start_processor.ps1 -ExecutionMode agent
# 不带参数会打开图形启动器
.\start_agent.ps1

# 重新生成采集器、中央服务和处理机 Agent 三个 Windows 发布包
.\build_release.ps1

# 当前单处理电脑部署：快速生成服务器和采集器两个包
.\build_deployment.ps1

# 生成包含最新三个发布包、源码、素材库、母版和解密工具的完整项目 ZIP
.\build_portable_project.ps1 -BuildReleases
```

## 本机与公用机切换

- 员工自己的处理端使用默认 `standalone`，启动器访问 `http://127.0.0.1:8010/app/new`，视频直读本机路径；旧工作台仍保留在 `/app`。
- 普通用户账号和数字人任务统一来自数字人网站；正式源码入口默认连接
  `https://video.lanyingjk01.com`，隔离测试入口连接 `http://127.0.0.1:8000`。
- 公用机使用独立发布包 `release/JianyingRenderServer-shared-windows-x64.zip`。它默认监听 `0.0.0.0`、继续用公用机自身的一套剪映顺序处理，不启用多 Agent 调度。
- 公用机页面继续显示同一组“本机处理 / 公用处理机”卡片；点击“本机处理”会返回员工电脑的 `http://127.0.0.1:8010/app`。

只生成公用机包：

```powershell
.\build_shared_processor.ps1
```

### 数字人账号与任务收件箱

工作台不再单独维护普通用户账号。隔离测试使用本机数字人网站账号：

```text
http://127.0.0.1:8000/admin
```

工作台登录时由数字人网站验证账号并签发短期令牌，不保存用户密码。进入“数字人任务”后，每 15 秒自动拉取当前账号自己的任务：单条文本语音视频可一键导入视频和精确字幕；上传音频或多片段任务提供 SeedVR2 清晰片段下载，人工粗剪后再选择成片。正式部署时在 `data/processor_config.json` 设置 `digital_human_server_url` 为正式数字人网站 HTTPS 地址，服务器现有账号无需迁移。

### 新版工作台与统一项目骨架

新版页面由工作台托管在 `/app/new`，成果库和声音中心分别使用
`/app/new/gallery`、`/app/new/voices`。新版登录页复用数字人网站账号，浏览器只持有
工作台设置的 HTTP-only 会话 Cookie；未登录访问会返回 `/app/new/login`，不会在
前端保存数字人访问令牌。

工作台已提供 `/api/new/projects` 统一项目接口作为后续业务模块的数据基础。一个项目
包含多条脚本行，每行分别保存当前音频、当前画面合成视频、原始视频片段、变体、字幕
绑定和历史素材版本。项目、素材、异步操作和外部批次关联全部绑定数字人账号；普通用户
只能访问自己的项目。

现有 `/app/new` 已直接提供 `minimax_h3_ref2va` 画面生成模式，不再要求用户切到另一套前端。
它复用同一个 JYD 项目、Excel/CSV 批量脚本、文章类型筛选、行勾选、声音中心和后期。H3 人物图
直接读取每行已有图片分配，不再二次勾选：`loop` 一行一张并按上传顺序循环，`count` 允许一张
连续对应多行；参考视频仍可按顺序/循环/连续复用映射并允许单行覆盖补充方向、衔接、画幅和 MP。
每行直接复用声音预览列中已生成并试听的 MiniMax 完整音频；提交 H3 时以该音频绑定的 raw cues
原稿快照为准，表格标点被规范化时不会误报成两个声音不一致。
用户点击该行或所选范围的“生成视频”即表示采用当前声音，系统在计算 H3 费用前自动锁定对应
音频版本，并在本机复用或生成 `subtitles.asr_alignment`。工作台只向云端发送绑定冻结原稿摘要、
完整音频摘要和 MiniMax 声音版本的 `jyd.h3-safe-cut-alignment.v1` 字词范围；云端校验后直接规划
安全切点，不访问其自身的 `127.0.0.1` ASR。相同声音重试复用本地缓存，不再增加独立的“审核
声音”操作。费用预览和明确确认只处理所选行，未选行不获得 H3 状态，也不会进入付费任务。

新项目的 H3 衔接默认是“首尾同图”：每行已分配的人物图作为该行全部自动分段共同的首帧/尾帧
Prompt 锚点；快速并行和尾帧串行仍可手动选择。
默认生成余量为 0.1 秒。项目保存并转发这两个值，历史项目继续使用已经冻结的配置。

H3 成功后会回填发起任务的原 `ProjectItem`，而不是新建孤立项目。工作台合并 H3 原生音画，
把同一母版拆成从 0 秒开始的静音 `base_video` 和一条 H3 权威音频，再让当前 H3 批次所选行
进入已有 FunASR 字幕、4B/BGM、变体和成果库。段级重试、主动重生成、取消、结果下载、账号池
和状态轮询均沿用云端 H3 执行合同；一个待确认或运行中的批次不能通过更换幂等键重复提交。

MiniMax H3 独立工作台通过 `h3.jyd_handoff.v2` 把同一 H3 母版拆出的静音 `base_video`、一条从
0 秒开始的 H3 权威音频和 H3 实际分段字幕窗口导入统一项目。最终播放音频必须来自 H3 成片；
输入 MiniMax 音频/raw cues 只作生成条件和来源审计。字幕文本使用冻结原稿，时间先受 H3 分段
窗口约束，再由 FunASR 对齐 H3 实际语音。相同 `handoff_id` 重复导入会幂等返回原项目，新一组 H3 分段则创建新项目，
不会覆盖已经进入后期的版本。项目、音频、字幕、基础视频和外部关联在同一个 SQLite 写事务
中登记；并发重复导入只创建一个项目，中途失败不会留下半成品。命令行入口为
`tools/jobs/import_h3_handoff.py`，本地受保护接口为
`POST /api/new/projects/import-h3-handoff`。

读取历史项目时仍兼容 `h3.jyd_handoff.v1`，但新交接不得生成 v1，也不得用输入 MiniMax 音频
覆盖 H3 音轨。v2 清单同时校验 H3 完整音画母版、分轨音频策略、字幕时间来源和包含 schema 的
稳定 `handoff_id`。

核心工作台现在把项目作为独立测试批次展示：左侧可在最近项目间切换，也可打开“新建批次”
后导入另一份脚本；切换或新建不会覆盖当前测试内容。已有批次可通过“追加表格”原子增加
多条脚本，任一任务 ID 重复时整批拒绝，不会只追加一半。配置表支持逐行勾选、全选及
`3,5,8-12` 形式的序号/任务 ID 快速选择；统一分析、MiniMax 声音和完整成片均可只处理
选中行，未选行不会进入对应付费任务。批次工具栏可按导入表格中的“文章类型”过滤行，
表头全选只选择当前筛选结果，适合按文体分别设置语速并生成声音。当前没有生成或分析任务时，
也可从批次选择区删除整个批次，并同步清理工作台受管的本地图片、声音、视频、变体和成果目录。
登录页面会继续每分钟补同步其他批次中仍显示为画面生成中的任务；切换批次不会让旧批次永久
停在“生成中”。补同步只查询既有幂等任务并下载已经完成的结果，不重新提交 RunningHub。
浏览器关闭期间不保存数字人访问令牌；重新打开并登录工作台后会立即补同步遗留状态。
页面底部的生成按钮和临时提交状态只绑定当前批次；旧批次可以继续在后台运行，但不会锁住
新批次的声音或多参考入口。切换后迟到的旧批次轮询响应也不会覆盖当前批次。

新版输入模块已经接通真实接口：用户可下载固定四列的 Excel 模板（`任务ID`、`脚本内容`、
`文章类型`、`分配账号`），上传 `.xlsx`/`.csv` 脚本；历史两列表仍可兼容导入。已有批次可
按任务 ID 回填后两列，当前脚本、声音、视频、字幕和分析均不失效。页面还支持批量上传
JPG/PNG/WEBP，并选择“每图连续复用 N 行”或“逐行循环”策略。任务 ID、
脚本、图片池、逐行当前图片和图片历史版本均由工作台保存，刷新页面可恢复。
上传人物图时未勾选脚本行会保持原有全项目图片池分配；勾选或用序号范围选择脚本行后上传，
则只把本次从本地选择的新图片在所选行内按 count/loop 循环，范围外行保持原图。每个所选本地
文件都作为新图片保存，不按名称或内容跳过；范围内仍可单行替换。

声音模块也已经接通真实接口：声音中心读取当前数字人账号的三个 MiniMax 官方音色及
已保存的克隆/融合音色，可先生成制作结果、试听后再保存到音色库；核心工作台切换默认
音色时优先只应用到已勾选行，其次应用到当前文章类型筛选范围，未勾选且未筛选时才应用到
全部脚本行，各行仍可单独覆盖。范围外已有音频及其后续绑定不会失效。显式确认费用后可生成音频、轮询
状态、试听、下载和失败重试。生成结果及 MiniMax
原始时间戳会保存为项目素材版本，流程停在声音审核边界，不会自动创建 RunningHub
画面任务。声音请求只提交脚本、音色和语音参数，不上传项目图片。
本地请求不写死视频提示词；行级未显式设置时，由数字人网站当前 RunningHub 配置提示词
统一接管，避免本地旧默认值覆盖完整配置。

画面模块 4A 已接通真实接口：用户再次确认 RunningHub 费用后，工作台后端调用数字人
后端原有任务链；此时才上传各行当前图片并与已审核音频绑定。随后轮询单/多片段状态，
云端会把每个数字人分段一对一送入固定 48G 的 SeedVR2；工作台在 `VIDEO_ENHANCING`
期间持续等待，完成后下载并保留所有 SeedVR2 清晰分段，再
保存按音频时长标准化的 `base_video`；多片段接缝使用 0.25 秒保时长叠化。页面显示真实
状态并支持预览、下载与失败阶段重试。音频完成后、4A 启动前仍可替换图片，4A 会使用
最后一次选择的当前图片。

4A 费用确认会先读取云端权威执行模式。默认 `same_account_v1` 时，管理员以及云端授权的
`Cx_ceshi` 等受控测试账号仍看到一组 RunningHub 账号，并由每个分段实际选中的同一账号完成
数字人与 SeedVR2；这不是退回测试账号自己的单 RunningHub 配置。云端网页开关和 ID级授权同时生效后返回
`dual_pool_v1`，页面分别显示“数字人账号池”和“SeedVR2 放大账号池”，两组每次重新默认全选、
都至少保留一个。无授权普通用户不显示资源池并继续自己的单账号；受控测试账号在开关关闭时
显示一控多单池，在开关开启时显示双池。
工作台冻结执行模式及两组内部账号 ID，不保存或显示 Key、指纹、Base URL 或 App ID。
云端账号摘要可附带最近一次安全 RH 币缓存；4A 费用确认在账号卡显示剩余 RH 币和缓存是否
过期。工作台不自行查询 RunningHub，也不保存完整 Key、请求体或第三方完整响应。
4A 费用确认明确显示当前“一控多/双池”；启动后每行按分段显示云端实际执行账号。一控多显示
同一账号完成数字人与放大，双池分别显示两个阶段账号，尚未分配的阶段显示“待分配”。这组
安全摘要随逐行操作持久化，刷新或重启后仍可恢复。

近百行启动先保存逐行不可变快照并立即返回，再由最多 4 个后台线程按稳定幂等键逐行上传和
交接；单行失败不阻断其他行，工作台重启后由下一次已登录状态轮询继续未交接行。开关后续
改变不会改写已有操作；云端返回模式与本地费用确认快照不一致时，该行明确失败而不盲目启动。

模块 4B 使用 `base_video`、MiniMax 原始句级时间戳、本机 CPU FunASR 字词时间、用户选择的真实字体和可选 BGM
生成浏览器完整预览配方，普通预览不启动剪映，也不提前导出中间 MP4。字幕固定居中
单行、最大宽度为画面 80%、距底部约 20%；长句按真实字体字宽在原 cue 时间内拆成
连续字幕，无法安全排版时标记 `REVIEW_REQUIRED`。语义重排把逗号后的完整分句作为边界，
并保护“十年”“近 5 万名”等数字量词不被拆开。若按需剪映导出失败而浏览器预览仍完整，
逐行重试只重新提交本地导出，复用当前画面、字幕和 BGM，不重新调用 RunningHub 或 MiniMax。
BGM 由程序测量人声与曲目的综合响度：普通音乐以低于口播 11 dB 为目标，自动限制在
`0.08..0.25`，分析失败时回退 `0.18`；标记为强人声的音乐不再被硬过滤，但会改用
低于口播 15 dB、`0.05..0.16` 的更低混音范围，失败时回退 `0.1136`。浏览器预览与
剪映导出读取同一冻结音量。BGM 从成片结尾向前铺设：曲目长于视频时使用其末尾等长区间；
曲目短于视频时最后一轮完整播放到曲目自然结尾，前面继续反向补足，轮次间使用 0.2 秒
交叉衔接。浏览器预览、普通导出和变体使用同一规则，最终结尾不再截断到曲目中途。
普通成片和变体还统一让 BGM 开头用 5 秒渐起、最后一个主视频片段用 2 秒渐隐；两段时长
分别通过 Render Job 的 `audios[].fade_in_us` 与 `source.fade_out_us` 参数传递，集中默认值可直接调整。
FunASR 不改写脚本、不决定断句，只在最终排版完成后校准每条字幕的真实发音边界；每个结果
仍被限制在所属 MiniMax raw cue 内。对齐结果按脚本和音频版本缓存，服务不可用或命中率不够
时进入 `REVIEW_REQUIRED`，不会继续使用会在长音频后段累计偏差的等字数时间分配。
完整音频明确返回空时间戳时，工作台会自动转成 16k 单声道 PCM，按 20 秒核心区和前后 1 秒
上下文分块识别，再按核心区归属合并绝对时间；脚本命中率、raw cue 边界和单调时间校验仍沿用
原严格规则。单条字幕进入 `REVIEW_REQUIRED` 时继续处理同批其他行，不再让第一条失败阻断整批。
用户明确下载普通成片时才按需调用现有剪映队列导出一次；后续变体直接把原始分段画面和同一
字幕/BGM 配方放入变体任务，不能要求先导出普通成片。4B 不重新调用 RunningHub，也不
自动生成变体。浏览器预览仍绑定已按音频时长标准化的 `base_video`；4B 按需导出和模块 6
把 RunningHub 各原始片段分别放入剪映主轨，按原分段计划精确占满各自时间区间，并静音
片段原声、从 0 写入一条完整 MiniMax 音频。供应商文件实际略短时只对对应画面做轻微
变速，不改变权威音频和字幕时间轴，因此不会逐段累计错位。

智能内容分析模块 5 已把数字人后端的单脚本分析接口接入工作台。Excel/CSV 导入和脚本编辑
只保存或失效快照，不自动分析；用户点击“生成声音预览和脚本分析”后，工作台才对本批声音目标中首次
导入或文本变化的 `ProjectItem` 发起分析，一行一次请求，单批最多并发 10 行。仅重新生成
