# AI 标题与固定封面开发文档

日期：2026-08-11

## 1. 目标与职责边界

每条项目任务只保存一份标题结果，由项目后处理、普通成片和后续全部变体共同继承。封面不再属于
模块 6 的人工变体参数，也不允许每个变体单独填写。

- 大模型只负责根据原脚本生成标题文字。
- 本地工作台负责校验、持久化、固定视觉参数和剪映渲染。
- 封面底图不从数字人视频截图。存在 `base_video` 时，以其
  `metadata.input_image_sha256`（兼容 `external_ref.image_sha256`）为权威，从当前图片和
  `asset_history.input_image` 中回溯生成该视频时冻结的原始人物图；没有基础视频快照的旧数据
  才回退到 `item.inputs.image`。匹配原图缺失时停止导出，不能静默使用当前图片生成错配封面。
- 没有合法标题时不生成占位封面，前端显示“等待 AI 标题”。
- 本阶段不调用真实付费大模型；先完成标题契约和渲染链。

## 2. 数据归属

统一内容分析成功后，标题同时保存在分析快照和 `item.settings.postprocess`。`title` 是唯一权威
值，另外两个字段是面向既有渲染器的确定性映射，不是第二套文案：

```json
{
  "title": {
    "line_1": "减脂真相",
    "line_2": "坚持更关键"
  },
  "cover_title": {
    "line_1": "减脂真相",
    "line_2": "坚持更关键"
  },
  "top_title": {
    "label": "",
    "headline": ""
  }
}
```

新生成标题第一、二行硬上限均为 5 个字符；两行不得含空格或换行，也不得完全
相同。为保证历史项目仍可再次导出，本地渲染读取层继续兼容已经保存的 9～14 字旧第二行，但
统一内容分析不会再生成这种长标题。
模型两行标题只用于封面。正文顶部使用与模型无关的固定单行“世界冠军带你自律”（字号 19）；
任一封面标题行为空或超长时只把标题分支标记为失败，不覆盖音乐、字幕或视觉分支的成功结果。

标题变化只使后处理成片失效，不重新调用 MiniMax 或 RunningHub。变体请求不再接受或保存独立
`cover`；历史客户端传入的该字段只兼容忽略，不能覆盖项目标题。

## 3. 固定封面参数

基准画布为 1080×1920、9:16，封面持续 3 帧。剪映 UI 的 Y 值按项目既有换算规则写为
`transform_y = UI_Y / 1920`。

| 项目 | 第一行 | 第二行 |
| --- | --- | --- |
| 字体 | 思源粗宋 / `SourceHanSerifCN-Heavy` / `6807742980271641102` | 同左 |
| 字号 | 30 | 22 |
| 颜色 | `#FADF4A` | `#F5F6F0` |
| 位置 | X=0，Y=-160 | X=0，Y=-655 |
| 缩放 | 100% | 100% |
| 字间距 / 行间距 | 0 / 6 | 0 / 6 |
| 对齐 | 水平居中 | 水平居中 |
| 阴影颜色 | `#000000` | `#1F1A05` |
| 阴影 | 90%，模糊 15%，距离 5，角度 -45° | 50%，模糊 15%，距离 5，角度 -45° |

底部黑框使用普通混合、50% 不透明度、100% 缩放、X=0、剪映 UI Y=-420。当前图片层实现把黑框
直接合成进封面 JPEG：中心比率 `0.625`，宽度比率 `1.0`，高度比率 `0.26`。上传图片先用
居中 cover 裁切适配实际草稿画布，再合成黑框；文字仍保留为可编辑剪映文本轨道。

封面插入时间线最前 3 帧，正文视频、语音、字幕、BGM、顶部标题、人名板和语义素材整体后移，
因此正文元素不会出现在封面上。

## 4. 大模型返回规划

现有“统一内容分析”在同一次 Ark 模型调用中包含 `title` 第四分支，禁止为了封面标题再
发起第二次付费调用。provider v4 响应结构中的标题部分为：

```json
{
  "title": {
    "line_1": "减脂真相",
    "line_2": "坚持更关键"
  }
}
```

提示词要求：

1. 只依据当前脚本，不补造疗效、数字、身份或结论。
2. 第一行表达主题钩子，建议 2～5 字且硬上限 5 字；第二行表达具体冲突、结果、方法或行动钩子，
   建议 4～5 字且硬上限 5 字。
3. 一眼能理解重点，避免“震惊”“一定要看”等空话、废话和无信息口号。
4. 两行共同形成一条标题：不能重复，也不能分别生成“封面版”和“视频版”。
5. 只输出结构化 JSON；不得返回字体、颜色、坐标、图片路径、素材 ID 或时间参数。
6. 标题自身不得复述违法低俗、歧视引战、暴力伤害、未成年人风险、隐私联系方式、私域引流、
   伪科学、药物诊疗或医疗效果承诺。低风险体重管理表达使用自然中性措辞；无法安全概括时输出
   “生活提醒/理性看待”，不得用谐音字、近形字、emoji、拼音或符号伪装敏感词。

云端与本地接收层都把 `title` 当作独立分支校验。模型输出经长度、空白、成对字段校验后，本地
一次性写入 `postprocess.title`，再映射到 `cover_title`。历史 `top_title` 只保留兼容读取；缓存键包含脚本 SHA-256、
分析 schema、provider 和 Prompt 版本；脚本不变时复用，脚本变化时仅使当前行标题失效。
本地 `normalize_cover_title()` 在保存和每次渲染前再次执行确定性安全改写，因此历史标题、
人工标题、浏览器预览、普通导出和变体不会绕过同一出口规则。

## 5. 渲染流程

```text
统一内容分析（单次 Ark）-> 保存唯一 title -> 映射 cover_title -> 4B 浏览器预览配方
                                      -> 普通成片导出：同一封面
                                      -> 模块 6 变体：继承同一封面
```

普通导出和变体都调用 `build_project_cover()` 构建同一固定配方。变体数量、背景色、贴纸和特效可以
变化，封面文字、底图和固定样式不参与差异组合。

## 6. 验收标准

1. 封面底图等于当前基础视频冻结哈希对应的原始人物图，不等于数字人视频帧，也不盲用后来
   重新映射的当前图片；浏览器预览、普通导出和变体使用同一解析规则。
2. 两行标题、字体、字号、颜色、位置、阴影和黑框参数与本文件一致。
3. 封面严格占 3 帧；正文所有轨道从第 4 帧开始。
4. 普通导出和所有变体冻结同一 `postprocess.title` 作为封面；正文顶部固定显示
   “世界冠军带你自律”，不读取模型标题，变体接口没有手工封面要求。
5. 标题缺失时无占位封面；非法标题在进入渲染队列前失败。
6. 标题设置变化不调用 MiniMax、RunningHub 或 SeedVR2。
7. 新 AI 标题第一、二行第 6 个字符、任一空白或两行相同都必须在云端接收前被拒绝；本地读取
   层仅为再次导出历史成片兼容第二行到 14 字。
8. 重复套用同一个项目图片 ID 不得清空已有基础视频或成片；旧远程任务重试必须继续使用原图片
   快照，从而保证封面人物图与视频人物一致。
