# 智能内容分析与语义字幕开发文档

> 创建日期：2026-08-06  
> 当前阶段：模块 8 已完成；自动化开发计划已闭环  
> 适用项目：`runninghub_mvp` 数字人服务端、`jyd_plain_json_probe` 剪映工作台  
> 更新约定：每个模块开始前确认范围，完成后在本文记录实际变更、验证结果和遗留问题，再进入下一模块。

## 1. 目标

对每条 `ProjectItem` 的完整原始脚本执行一次结构化内容分析，第一期同时完成：

1. 返回供本地音乐库匹配使用的全局 `music_intent`。
2. 返回不增删、不改写、不调序的 `subtitle_units`，供工作台结合 MiniMax 原始时间轴和真实字体宽度生成字幕。

第一期不实现前景图片关键词，不让大模型生成字幕时间戳，也不让大模型直接选择本地音乐文件。

## 2. 已确认的产品决策

- 豆包 Ark API Key 保存于现有数字人服务端的用户管理配置中，沿用现有第三方密钥加密方式。
- 浏览器和剪映工作台不持有豆包 Key；工作台通过数字人服务端调用内容分析。
- 一次大模型请求同时返回音乐意图和字幕语义单元。
- 音乐由工作台本地匹配器从 46 首素材中直接选择最优一首，不展示 Top3。
- 用户可以手动更换音乐；手动选择后，普通刷新和下游重算不得被 AI 静默覆盖。
- MiniMax 原始时间戳永久保留。大模型只提供字符位置和语义关系，时间映射由程序确定。
- MiniMax `raw_cues` 是不可覆盖的时间轴事实源，语义断句只能生成派生的 `render_cues`。
- 音乐分析和字幕分析分别校验、分别保存状态；一部分失败不得丢弃另一部分的合法结果。
- 字幕仍使用抖音美好体 11 号真实字宽和画面最大宽度 80% 做最终硬校验。
- 模块 6 变体冻结继承模块 4B 已确定的 BGM，不把音乐作为变体维度。
- 内容分析失败只触发本地安全降级，不重新调用 MiniMax、RunningHub，不触发剪映导出，也不使已完成的基础视频失效。
- 豆包内容分析服务端统一并发上限默认设为 10，超出请求排队；当前单 Web 进程部署下由进程内共享信号量统一执行。
- 未经单独授权，不调用真实付费接口、不部署生产环境、不修改云端账号数据库。

## 3. 系统边界

```text
浏览器
  -> 剪映工作台 /api/new/*
  -> 数字人服务端 /api/workbench/content-analysis
  -> 豆包 Ark
  -> music_intent + subtitle_breaks（只含断点编号）
  -> 数字人服务端按原文生成公开 subtitle_units
  -> 工作台本地字幕排版 + 本地音乐 Top1 匹配
```

数字人服务端负责用户权限、豆包配置、模型调用、严格 JSON 校验和分析缓存。剪映工作台负责保存项目分析快照、字符到时间轴映射、真实字体测宽、本地音乐评分、预览、手动覆盖和变体继承。

## 5. 模块 1 范围

### 5.1 本模块要做

- 在数字人服务端增加不依赖豆包 SDK 的内容分析契约模块。
- 定义固定的音乐意图枚举和严格字段范围。
- 定义完整覆盖原脚本的字幕语义单元结构。
- 明确字符位置、连接词绑定和断点偏好语义。
- 实现纯本地契约校验：检测漏字、改字、重复、乱序、越界、重叠和空单元。
- 提供合法与非法 JSON 测试夹具和自动化测试。
- 输出稳定 JSON Schema，供后续豆包结构化输出和工作台解析共同使用。

### 5.2 本模块不做

- 不新增数据库表或迁移。
- 不新增管理员页面、API 路由或 Ark 客户端。
- 不调用豆包，不产生费用。
- 不修改 MiniMax 时间戳和现有字幕排版算法。
- 不修改 46 首音乐运行时素材清单或选择页面。
- 不实现前景图片关键词。

### 5.3 字符位置规范

- 原始脚本必须按原样传入，不先做 trim、换行归一化、全半角转换或标点替换。
- `start`、`end` 使用 Python 字符串的 Unicode code point 索引。
- `start` 为包含位置，`end` 为不包含位置。
- 必须满足 `original_script[start:end] == text`。
- `subtitle_units` 按位置升序、首尾相接，完整覆盖原始脚本；所有 `text` 拼接后必须与原脚本逐字符一致。
- 大模型不返回 `start_us`、`duration_us` 或任何虚构时间戳。

### 5.4 字幕语义

- `kind` 用于标识连接词、普通词、数字、专有名词、关联短语、标点和空白。
- `bind` 表示当前单元与左侧、右侧或两侧的语义绑定。
- `break_after` 表示当前单元后优先断开、允许断开或应避免断开。
- `bind=right` 可用于“那么、所以、但是”等承接词，避免留在上一条字幕末尾。
- 数字、专有名词和不可拆关联短语作为完整单元，工作台不得在单元内部断开。

### 5.5 音乐意图

模型只返回受控内容特征，不返回音乐文件名、路径或 `bgm_identity`。第一版音乐意图包含：

- 内容场景与内容形式。
- 主情绪、次情绪和情绪正负向。
- 能量、节奏、严肃度、温暖度、紧张度。
- 口播密度和人声偏好。
- 匹配置信度及不适合的音乐特征。

具体枚举和值域以模块 1 契约代码和生成的 JSON Schema 为权威来源。

## 6. 版本与失效原则

- 契约版本固定写入响应，第一版为 `jyd.content-analysis.v1`。
- 后续增加前景图片关键词时发布新契约版本，不向 v1 空塞 `visual_cues`。
- 脚本内容变化使音乐和字幕分析同时失效。
- 音频变化但脚本未变化时复用语义分析，只重新做时间映射和音乐时长检查。
- 字体、字号或最大宽度变化只重新做本地字幕排版。
- 音乐标签库或评分版本变化只重新做本地音乐匹配。

## 8. 后续内容分析与字幕模块的强制边界

以下规则自 2026-08-06 起作为模块 4 至模块 7 的实现约束。模块 3 只负责用户级豆包配置和独立 Ark 客户端，不提前实现这些业务流程，但其客户端错误模型和日志脱敏必须支持这些边界。

### 8.1 字幕语义与时间轴的职责分离

- 大模型只返回 `subtitle_breaks` 断点编号，不返回字幕文本；服务端确定性转换得到公开
  `subtitle_units`，用于表达可选语义边界和断点偏好。
- 大模型不得返回、推测或补写 `start_us`、`end_us`、`duration_us`。
- MiniMax 异步语音结果中的原始字幕时间戳必须作为 `raw_cues` 永久保留，不得被大模型结果或后续排版覆盖。
- `render_cues` 是可按脚本、语义分析版本、字体、字号和最大宽度重新生成的派生数据；删除或失效 `render_cues` 不得删除 `raw_cues`。

固定处理顺序：

```text
原始脚本
→ 服务端标注可选 B 边界
→ 大模型选择 prefer_after / allow_after
→ 服务端按原文切片生成 subtitle_units
→ 按字符位置与 MiniMax raw_cues 做单调映射
→ 在 raw_cues 的真实时间边界内计算语义单元时间范围
→ 按真实字体宽度和最大宽度规则生成 render_cues
```

如果 MiniMax 只提供 cue 级起止时间，而语义断点落在 cue 内部，程序可以在该 cue 的真实起止范围内进行确定性分配；该时间是基于 MiniMax 锚点的派生时间，不得记为大模型时间戳。映射无法可靠建立时，字幕分支失败并回退到现有 `raw_cues + 标点/真实宽度` 排版，不重新生成语音。

### 8.2 字幕字符索引的安全修复

模块 1 的严格契约仍是最终入库校验标准，但允许在严格校验前执行一次受限修复：

1. `subtitle_units` 非空，且每个单元的 `text` 非空。
2. 单元顺序不变，所有 `text` 直接拼接后必须与原始脚本逐 Unicode code point 完全一致。
3. 只有 `start/end` 不正确，文字、顺序、单元边界和语义属性均未变化。
4. 服务端按单元文本的累计字符长度重新计算 `[start, end)`，然后再次执行模块 1 的完整严格校验。

不得通过模糊搜索、自动改字、忽略空白、标点归一化或调整单元顺序来“修复”结果。只要拼接文字与原文不完全一致，字幕分支即判定失败并使用安全降级。

### 8.3 音乐与字幕必须独立校验和保存

豆包仍在一次请求中同时返回 `music_intent` 和 `subtitle_breaks`，但服务端不得只用顶层组合模型的一次成败决定两部分结果。处理时必须先解析顶层 JSON，再分别执行：

- `music_intent` 结构和值域校验；
- `subtitle_breaks` 结构与候选编号校验，再按原文确定性生成并校验 `subtitle_units`。

工作台分析快照至少保存：

```json
{
  "music_analysis_status": "SUCCESS | FAILED",
  "subtitle_analysis_status": "SUCCESS | FAILED"
}
```

生命周期实现可以额外增加 `NOT_REQUESTED` 或 `PENDING`，但最终结果必须能明确区分两条分支。每条分支可以保存稳定错误码和脱敏错误摘要。

分支处理矩阵：

| 音乐 | 字幕 | 处理结果 |
| --- | --- | --- |
| 成功 | 成功 | 保存两部分结果，分别执行本地 Top1 和字幕映射排版 |
| 成功 | 失败 | 保存 `music_intent` 并继续 Top1；字幕回退现有排版，不重新调用 MiniMax |
| 失败 | 成功 | 保存 `subtitle_units` 并继续字幕映射；BGM 按“手动选择 → 项目默认 → 无 BGM”降级 |
| 失败 | 失败 | 整体分析失败，但仍执行字幕和音乐的本地安全降级 |

只有请求没有获得任何可解析结果，或音乐与字幕两部分均未通过校验时，才把整个内容分析记为完全失败。一部分成功时应记为部分成功，且成功分支必须先保存；有限重试不得清除或静默覆盖已经合法的分支结果。

### 8.4 降级与副作用边界

- 字幕专用请求失败或结果未通过逐字符校验：立即使用本地确定性切分；本地切分成功视为字幕分支成功，不把整体状态降为 `PARTIAL`。只有本地也无法安全拆分时才记录字幕失败，并继续使用 MiniMax `raw_cues` 和现有标点/真实宽度排版。
- 音乐分析失败：优先保留用户手动选择，其次使用明确的项目默认音乐，否则无 BGM。
- AI 结果在任何情况下都不得覆盖用户已经手动选择的 BGM，除非用户明确执行“恢复 AI 推荐”。
- 任一分支失败都不得阻止已有基础视频和 4B 浏览器预览；无 BGM 是合法降级状态。
- 内容分析失败不得重新调用 MiniMax、RunningHub，不得触发剪映生成或导出，不得改变已完成基础视频的有效状态。

### 8.5 隐私、日志与模块 1/2/3 的关系

- 普通日志不得记录豆包 API Key、豆包完整原始响应、完整用户脚本或其他用户敏感内容。
- 日志只记录请求 ID、用户/项目的内部稳定标识、分支状态、契约版本、模型版本、耗时、稳定错误码和经过长度限制的脱敏摘要。
- 模块 1 当前提供的是“音乐与字幕均合法”时的最终组合契约和严格解析器，尚未接入业务流程。模块 4 实现时必须增加分支级解析入口，不能把现有组合解析器作为唯一成败闸门。
- 模块 1 对错误 `start/end` 的拒绝仍然正确；模块 4 已在进入该严格校验前增加满足 8.2 条件的确定性索引修复，模块 6 在时间轴映射前继续复核服务端结果。
- 模块 2 只接收已经合法的 `music_intent` 并执行本地 Top1，不读取字幕结果，因此天然支持“音乐成功、字幕失败”的路径，无需修改。
- 模块 3 只保存用户级 Ark 连接参数并提供独立传输客户端；模块 4 已实现分支独立校验、缓存和脱敏业务日志。
- 截至本文更新时，模块 1 至模块 4 的自动化测试均为 mock，没有调用豆包、MiniMax、RunningHub 或剪映导出，也没有实现会破坏上述边界的运行时串联逻辑。

### 9.1 本模块要做

- 在数字人服务端新增用户一对一的豆包 Ark 配置，继续以数字人网站账号作为唯一普通用户来源。
- 在现有管理员用户表单中增加启用状态、Ark API Key、Base URL、模型、请求超时和有限重试次数。
- API Key 复用现有 Fernet 机制加密保存；页面只允许写入或轮换，永不回显明文，留空时保留原密钥。
- 新增只负责 Ark OpenAI 兼容 HTTP 协议的独立客户端，支持依赖注入、结构化异常和对超时、429、明确 5xx 的有限重试。
- 客户端错误和日志只保留安全状态码、请求 ID、尝试次数等诊断信息，不包含 API Key、完整请求、完整响应或用户脚本。
- 新增 `0021` Alembic 迁移、管理员配置测试、加密/轮换测试、客户端 mock 测试和迁移测试。

### 9.2 本模块不做

- 不新增内容分析业务 API，不向工作台暴露配置或 Key。
- 不编写最终内容分析 Prompt，不调用模块 1 组合契约，不解析或保存 `music_intent`、`subtitle_units`。
- 不实现分支独立校验、缓存、索引修复、MiniMax 时间轴映射或音乐 Top1 接入。
- 不调用真实豆包、MiniMax、RunningHub 或剪映，不产生第三方费用。
- 不部署生产环境，不迁移或修改云端账号数据库。

### 9.3 配置与客户端规则

- 配置按 `users.id` 一对一保存，不采用浏览器 Key、工作台本地 Key 或仓库 `.env` 中的全局用户凭证。
- 默认 Base URL 为 `https://ark.cn-beijing.volces.com/api/v3`；模型由管理员按用户填写。
- 未启用时允许先保存空 Key 或空模型；启用时必须已有可解密 Key 且模型非空。
- 超时范围固定为 1～600 秒，额外重试次数固定为 0～5；这些值只定义客户端能力，模块 3 不会自行发起请求。字幕专用分支会用单次尝试覆盖关闭传输重试，失败后直接转本地确定性切分。
- 客户端返回服务商响应对象给后续模块处理；业务 Schema、部分成功语义和缓存属于模块 4。

## 10. 模块 4 开发范围（完成后记录）

### 10.1 已实现

- 数字人服务端统一内容分析业务接口、固定 Prompt 与 Ark 严格 JSON Schema。
- 音乐/字幕分支独立校验、状态和错误摘要，以及合法分支的数据库缓存。
- 完整失败可再次请求、部分/完整成功缓存复用、强制刷新时成功分支保护。
- 服务端统一并发 10、队列等待和同脚本进程内去重。
- 工作台短期令牌鉴权、脚本长度上限、日志脱敏、迁移和 mock 自动化测试。

### 10.2 明确未实现

- 不在工作台项目数据库保存分析快照，不处理工作台项目版本失效。
- 不把 `subtitle_units` 映射到 MiniMax `raw_cues`，不生成 `render_cues`。
- 不调用模块 2 的本地音乐 Top1，不写入或覆盖项目 BGM。
- 不调用真实豆包，不做人工真实输出质量验收，不部署生产环境。
- 不支持多 Web 进程共享并发；未来扩容前必须将进程内信号量替换为数据库或 Redis 共享租约。
