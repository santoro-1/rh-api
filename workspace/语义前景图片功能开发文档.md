# 语义前景图片功能开发文档

更新时间：2026-08-07  
状态：需求已对齐，待新任务按本文实施（紧急）

## 0. 新任务开工摘要

本功能要解决的不是“文案里出现关键词就无条件贴图”，而是：

1. 工作台从受控的本地语义图片目录中召回关键词候选。
2. 云端大模型根据完整语境判断候选是具体对象、成语、比喻、否定还是词语引用。
3. 只有通过语义判断和本地硬规则的候选才生成贴图建议。
4. 工作台使用当前音频的 MiniMax `raw_cues` 把字符位置确定性换算成时间。
5. 用户可以预览、启用、禁用、换图和锁定人工修改。
6. 最终配方进入新版工作台本地 4B 剪映渲染，不调用 RunningHub，不重新生成语音。

新任务应完成一个可验收的端到端 MVP，而不只是再写一层抽象契约。最低完成标准是：

- `每天吃一个鸡蛋` 能在正确时间显示已配置的鸡蛋素材。
- `鸡蛋里挑骨头`、`这不是鸡蛋` 和讨论“鸡蛋”一词本身时不自动显示。
- 用户能在工作台看到建议并手动关闭或更换。
- 浏览器预览和剪映成片读取同一份最终贴图配方。
- 贴图失败不影响字幕、BGM、语音、基础视频和已有成片。

本文是新任务的需求事实来源。实现前仍必须按两个项目的 `AGENTS.md` 重新读取当前代码、
Git 状态和定向测试，不得只依据本文或旧对话摘要修改。

## 1. 文档目的

本文定义新版剪映工作台“根据文案语义在对应时间弹出前景图片”的产品规则、数据契约、
云端与本地职责、实施顺序和验收标准。

本文是 `智能内容分析开发文档.md` 中“前景图片关键词”后续功能的专项设计文档。现有
`jyd.content-analysis.v1` 继续只负责音乐意图和字幕语义，不在原契约中追加空字段或改变
既有行为。

## 2. 产品目标

用户为本地图片素材配置关键词或语义概念。程序在文案中发现候选词后，由大模型结合完整
语境判断该处是否确实在描述一个适合展示的具体对象，再由新版工作台根据 MiniMax 原始
时间戳把图片放入浏览器预览和剪映草稿的正确时间位置。

典型示例：

- `每天吃一个鸡蛋`：这里的“鸡蛋”是具体食物，应显示鸡蛋图片。
- `鸡蛋里挑骨头`：这里是惯用表达，不应显示鸡蛋图片。
- `这不是鸡蛋`：默认不显示，避免对否定对象进行错误强调。
- `“鸡蛋”这两个字怎么写`：讨论的是词语本身，不显示实物图片。

本功能应被称为“语义前景图片”，而不是简单的“关键词弹图”。

## 3. 非目标

第一版不实现以下内容：

- 不允许大模型生成或猜测本地文件路径。
- 不让大模型生成 `start_us`、`end_us` 或任何音视频时间戳。
- 不从互联网自动搜索未审核图片。
- 不改变主视频、语音或字幕时间轴。
- 不把语义图片当作全屏插片，不切开数字人主视频。
- 不承诺第一版自动识别人脸和任意主体位置。
- 不在大模型不可用时直接退化为无条件关键词匹配。
- 不修改旧网页任务记录或旧网页生成链路。

## 4. 总体流程

```text
本地受控图片素材库
  -> 本地扫描文案并产生关键词候选
  -> 云端大模型判断每个候选所处语境
  -> 工作台严格验证模型结果
  -> 使用 MiniMax raw_cues 做字符到时间的确定性映射
  -> 本地选择具体图片并执行密度、冲突和安全区规则
  -> 用户预览、删除、换图或手动调整
  -> 浏览器预览
  -> 写入剪映上层轨道并导出
```

## 5. 职责划分

### 5.1 本地工作台负责

- 管理受控图片素材库和素材文件。
- 根据素材别名在脚本中查找候选位置。
- 给每个候选生成稳定 `candidate_id`、字符开始位置和结束位置。
- 只向云端发送概念元数据，不发送本地文件路径。
- 校验模型返回的候选 ID、概念 ID、决策值和置信度。
- 根据 MiniMax `raw_cues` 计算真实出现时间。
- 选择具体素材并执行去重、限流、位置和字幕避让。
- 保存自动选择和人工修改状态。
- 在浏览器和剪映草稿中使用同一份最终配方。

### 5.2 云端网站负责

- 接收脚本、脚本哈希、候选位置和允许选择的概念。
- 调用大模型进行语境消歧、重要度判断和是否展示判断。
- 对视觉分析结果进行严格契约校验。
- 按用户、脚本哈希、模型、提示词版本、契约版本和候选目录版本缓存。
- 视觉分支失败时返回合法失败状态，不影响音乐、字幕和既有音视频。
- 日志只记录哈希、数量、状态、耗时和错误码，不记录完整脚本。

### 5.3 大模型负责

- 判断候选词是具体含义、成语、比喻、否定、词语引用还是路过提及。
- 在程序提供的候选概念中选择一个 `concept_id`。
- 判断该候选是否值得在画面上展示。
- 输出重要度、置信度和结构化原因码。

大模型不负责发现本地文件、不负责最终选图、不负责画面位置，也不负责时间戳。

## 6. 本地图片素材目录

第一版使用受控目录，不允许任意模型概念直接进入生产渲染。每个语义概念至少保存：

```json
{
  "schema": "jyd.semantic-visual-catalog.v1",
  "concept_id": "food.egg",
  "name": "鸡蛋",
  "aliases": ["鸡蛋", "蛋"],
  "description": "作为食物、营养成分或烹饪材料出现的鸡蛋",
  "asset_ids": ["egg_transparent_01", "egg_breakfast_02"],
  "default_position": "top_right",
  "default_scale": 0.24,
  "enabled": true
}
```

素材使用稳定 `asset_id`。路径只存在本地素材清单中，不进入云端响应。首批素材优先使用透明
PNG、WebP 或已采集为剪映贴纸的资源，并记录预览图、尺寸、透明区域和可用状态。

别名匹配采用最长优先，并返回全部可能概念。例如同一个词对应多个含义时，模型只能在程序
提供的允许概念中选择，不能凭空生成新的概念 ID。

## 7. 视觉分析契约

### 7.1 请求

```json
{
  "schema_version": "jyd.visual-analysis.request.v1",
  "original_script": "每天吃一个鸡蛋有助于补充营养。",
  "script_sha256": "...",
  "catalog_version": "2026-08-07.1",
  "candidates": [
    {
      "candidate_id": "candidate-001",
      "text": "鸡蛋",
      "char_start": 5,
      "char_end": 7,
      "allowed_concepts": [
        {
          "concept_id": "food.egg",
          "description": "具体食物或营养语境中的鸡蛋"
        }
      ]
    }
  ]
}
```

字符位置必须由程序预先计算。云端应验证：

```text
original_script[char_start:char_end] == text
```

### 7.2 响应

```json
{
  "schema_version": "jyd.visual-analysis.v1",
  "script_sha256": "...",
  "catalog_version": "2026-08-07.1",
  "decisions": [
    {
      "candidate_id": "candidate-001",
      "decision": "SHOW",
      "concept_id": "food.egg",
      "usage": "literal",
      "importance": 0.86,
      "confidence": 0.95,
      "reason_code": "LITERAL_CONCRETE_OBJECT"
    }
  ]
}
```

每个输入候选必须且只能返回一次。响应不得包含本地路径和时间字段。

### 7.3 决策与原因码

`decision` 只允许：

- `SHOW`：语境明确且适合展示。
- `REVIEW`：可能适合，但默认关闭并等待人工确认。
- `SKIP`：不展示。

第一版至少支持：

- `LITERAL_CONCRETE_OBJECT`
- `SKIP_IDIOM`
- `SKIP_METAPHOR`
- `SKIP_NEGATED`
- `SKIP_META_MENTION`
- `SKIP_PASSING_MENTION`
- `SKIP_UNCERTAIN`
- `SKIP_NO_ASSET`

## 8. 调用和版本策略

现有 `jyd.content-analysis.v1` 保持不变。第一版推荐新增独立
`jyd.visual-analysis.v1`，并让它与现有内容分析并发执行：

- 图片提示词和契约可以独立迭代。
- 图片失败不会破坏已经稳定的音乐和字幕分支。
- 图片可以独立重试和缓存。
- 图片素材目录变化时，不需要让音乐和字幕缓存失效。

完成真实质量评估后，如果模型稳定性和成本数据支持合并，再发布聚合型
`jyd.content-analysis.v2`。不得直接修改 v1 的字段集合。

## 9. 字符到时间的确定性映射

工作台复用现有字幕字符时间映射原则，以 MiniMax `raw_cues` 为唯一时间事实源：

- 大模型的字符位置只用于定位语义锚点。
- 图片开始时间取关键词首个可发音字符的开始时间。
- 可在实际发音前最多提前 100～150 毫秒，但不得早于正文开始时间。
- 默认显示 1.8 秒，允许根据语句剩余时间限制在 1.4～2.2 秒。
- 不得超过视频总时长，也不得与封面时间重叠。
- 没有可靠 `raw_cues`、原文不一致或时间精度不足时，自动图片进入失败或待复核状态。
- 不得修改、覆盖或重新生成 `raw_cues`。

脚本、当前音频、raw cues 或素材目录版本变化时，相关自动结果必须重新验证；人工锁定的配方
不得被静默覆盖。

## 10. 最终图片配方

语义判断和最终选图分开保存。工作台最终配方示例：

```json
{
  "schema": "jyd.project-visual-overlays.v1",
  "bound_script_sha256": "...",
  "bound_audio_asset_id": "...",
  "bound_catalog_version": "2026-08-07.1",
  "overlays": [
    {
      "overlay_id": "overlay-001",
      "candidate_id": "candidate-001",
      "concept_id": "food.egg",
      "asset_id": "egg_transparent_01",
      "start_us": 3520000,
      "duration_us": 1800000,
      "position": "top_right",
      "scale": 0.24,
      "opacity": 1.0,
      "selection_mode": "auto",
      "locked": false
    }
  ]
}
```

用户换图、删除、移动、缩放或调整时间后，对应项设置为
`selection_mode=manual`、`locked=true`。重新分析只能更新未锁定的自动项。

## 11. 自动筛选和密度规则

推荐第一版默认值：

- `decision=SHOW` 且 `confidence >= 0.85` 才自动启用。
- `0.65 <= confidence < 0.85` 显示为待确认建议，默认关闭。
- 低于 `0.65` 直接跳过。
- 同一时刻最多出现一张语义图片。
- 两张图片之间默认至少间隔 6 秒。
- 每分钟最多自动启用 5 张。
- 同一概念或同一素材至少间隔 20 秒才可重复。
- 时间冲突时优先保留重要度更高、置信度更高的候选。
- 云端不可用时保留候选供人工选择，不执行无条件关键词自动弹图。

置信度只作为模型信号之一，不能替代契约校验、素材存在性和程序硬规则。

## 12. 画面和剪映规则

语义图片属于主视频之上的局部前景轨道：

- 不切割、不移动主视频。
- 不移动语音和字幕。
- 第一版只使用左上、右上安全区。
- 避开底部字幕安全区和画面中央常见人物区域。
- 默认宽度约为画面宽度的 18%～28%。
- 同一时间只出现一张。
- 第一版可以先使用静态限时出现；动画作为独立增强项。
- 浏览器预览与剪映导出必须读取同一份最终配方。

现有剪映贴纸轨道已经支持开始时间、持续时间、角落、缩放、旋转和透明度。实现时可以复用
底层草稿处理能力，但素材管理上应新增独立“语义前景图片”类型，不能与全屏贴纸或四角装饰
贴纸混为同一个产品类别。

## 13. 工作台交互

每条脚本行增加“语义配图”状态和入口，至少显示：

- 分析中、已完成、部分成功、失败、待复核。
- 已启用图片数量和待确认数量。
- 候选原文及附近语境。
- 模型决策、原因和置信度。
- 当前素材缩略图、出现时间、持续时间和位置。

用户可以：

- 启用或禁用候选。
- 替换为同概念下的其他素材。
- 调整位置、尺寸、开始时间和持续时间。
- 锁定人工修改。
- 只重试视觉分析，不重新调用 MiniMax、RunningHub 或剪映渲染。

## 14. 缓存、失效和日志

云端视觉缓存键至少包括：

- 用户 ID。
- 脚本 SHA-256。
- 模型。
- 视觉契约版本。
- 视觉提示词版本。
- 候选集合哈希。
- `catalog_version`。

本地最终配方还必须绑定当前音频素材 ID 和 raw cues 来源。失效只影响视觉分支，不删除已有
音视频、字幕、音乐或用户手动选择。

日志记录：

- `correlation_id`、项目 ID、item ID。
- 脚本哈希和候选数量。
- SHOW/REVIEW/SKIP 数量。
- 缓存命中、模型请求耗时、映射结果和错误码。

日志不得记录 MiniMax Key、完整脚本、本地绝对素材路径或模型完整原始响应。

## 15. 推荐开发顺序

1. 固化契约、原因码、素材目录格式和测试样例。
2. 实现本地素材目录及关键词候选召回，不连接大模型。
3. 实现云端视觉语境分析、独立缓存和部分失败响应。
4. 实现工作台字符到 MiniMax 时间戳映射、版本绑定和缓存失效。
5. 实现自动素材选择、密度控制和人工锁定数据。
6. 实现工作台审核界面和浏览器动态预览。
7. 接入剪映局部前景轨道并验证成片。
8. 再增加进入/退出动画、人脸避让、变体换图和候选概念发现。

## 16. 测试与验收

### 16.1 语义判断

- `每天吃一个鸡蛋` 必须显示。
- `鸡蛋里挑骨头` 必须不显示。
- 否定、比喻、词语引用、列表顺带提及必须分别覆盖。
- 同词多义、重复关键词和多个候选概念必须覆盖。
- 模型不得返回未提供的候选 ID 或概念 ID。

### 16.2 契约和时间

- 字符切片必须逐字等于候选文本。
- 模型响应出现任何时间字段必须拒绝。
- 时间只能由当前音频的 MiniMax `raw_cues` 派生。
- 缺少 raw cues、原文不一致和时间不足必须安全失败。
- 封面偏移后图片不得出现在封面时间内。

### 16.3 状态和人工操作

- 脚本或音频变化后自动结果失效。
- 人工锁定的图片不得被重新分析覆盖。
- 视觉分析失败不得影响音乐、字幕和已有音视频。
- 同一请求重试不得重复创建配方或重复计费。

### 16.4 预览和导出

- 浏览器预览和剪映成片的素材、时间、位置、尺寸一致。
- 图片不遮挡字幕安全区。
- 图片不会改变主视频、语音、字幕和最终总时长。
- 多张图片满足间隔、数量、去重和不重叠规则。

## 17. 上线边界

本功能应先使用测试账号和小型素材目录完成自动化测试、浏览器验收及本地剪映草稿验收。
未完成真实样例验收前，不部署生产，不迁移生产数据库，不扩大到自由概念发现，也不默认对
所有项目自动启用。

## 18. 2026-08-07 当前代码基线

### 18.1 数字人云端项目

当前 `runninghub_mvp` 已具备：

- 稳定的 `jyd.content-analysis.v1` 音乐意图和字幕语义契约。
- 用户级豆包 Ark 配置、统一并发限制、缓存、部分成功和失败重试。
- 工作台专用 `POST /api/workbench/content-analysis`，一次只接收一条精确脚本。
- 不记录完整脚本和模型完整响应的结构化日志边界。

当前尚不具备：

- 视觉候选请求/响应契约。
- 视觉 Prompt、结果校验和独立缓存。
- 工作台视觉分析 API。

不得为了省事向现有 `jyd.content-analysis.v1` 增加可选视觉字段。视觉分析必须保持独立版本和
独立失败边界。

### 18.2 新版工作台项目

当前 `jyd_plain_json_probe` 已具备：

- 每行 `ProjectItem` 的脚本、内容分析快照、MiniMax `raw_cues`、字幕映射和 BGM Top1。
- 脚本/音频版本绑定、分支失败隔离、人工 BGM 优先和 4B 配方冻结。
- 浏览器 4B 预览和本地剪映渲染队列。
- 已采集贴纸素材库以及剪映贴纸轨道的开始时间、持续时间、角落、缩放、旋转和透明度能力。

当前尚不具备：

- 独立的语义图片目录和关键词别名清单。
- 候选召回、视觉分析快照和字符到贴图时间的映射。
- 每行语义配图审核界面和浏览器动态贴图预览。
- 4B 配方中的语义贴图字段及对应成片写入。

现有 `sticker_library` 是“整段全屏贴纸”，`corner_sticker_library` 是“四角装饰贴纸”，两者
都不能直接作为语义图片产品目录暴露给用户。实现可以复用其底层剪映素材复制和轨道写入
能力，但必须新增独立的 `semantic_visual_library` 目录、清单和接口。

### 18.3 当前工作区保护

开始开发时必须先检查两个仓库的 Git 状态。2026-08-07 检查时，云端存在尚未提交的
RunningHub 管理员资源池开发改动；工作台存在用户维护的音频、字体、日志和其他代码改动。
这些都不是本功能可以清理、覆盖或回滚的内容。开发者应避开无关文件，并在交付时明确列出
本功能实际修改的文件。

## 19. 紧急 MVP 的素材策略

第一版采用“独立语义目录，优先复用剪映贴纸包”的方式，以尽快完成可靠成片：

```text
data/libraries/semantic_visual_library/
  catalog.json
  bundles/
    food_egg_01/
      visual.json
      preview.png
      resources/...
```

`visual.json` 至少包含：

```json
{
  "schema": "jyd.semantic-visual-asset.v1",
  "asset_id": "food.egg.transparent.01",
  "concept_id": "food.egg",
  "name": "鸡蛋透明贴图",
  "render_type": "sticker_bundle",
  "sticker_json": "sticker.json",
  "preview_file": "preview.png",
  "enabled": true
}
```

MVP 必须支持 `sticker_bundle`，因为当前剪映轨道写入已经验证了定时、角落、缩放和透明度。
普通透明 PNG/WebP 的直接视频上层轨道可作为后续 `render_type=raster_image` 扩展；不要为了
同时支持两种渲染素材而推迟首个端到端版本。若首批素材当前只有 PNG，应先通过受控导入工具
转换或采集成语义贴纸包，并保持稳定 `asset_id`。

语义目录不得直接复用全屏贴纸清单的产品分类，也不得把本地绝对路径发到云端。

首轮验收目录至少准备以下概念：

- `food.egg`：鸡蛋。
- `food.corn`：玉米。
- `food.sweet_potato`：红薯。
- `food.oat`：燕麦。
- `food.soy_milk`：豆浆。
- `food.vegetable`：蔬菜或绿叶菜。

其中 `food.egg` 必须有至少两个可切换素材，用于验证同概念换图和人工锁定。

## 20. MVP 的模块拆分和代码落点

文件名可以根据现有工程风格微调，但职责不能混在一个巨型模块中。

### 20.1 模块 A：本地目录和候选召回

工作台建议新增：

- `src/jyd_probe/semantic_visual_catalog.py`
- `src/jyd_probe/semantic_visual_candidates.py`
- `tests/test_semantic_visual_catalog.py`
- `tests/test_semantic_visual_candidates.py`

完成：目录加载、安全路径校验、版本哈希、最长别名匹配、重叠候选处理、稳定
`candidate_id`、字符位置逐字校验和无素材候选剔除。

### 20.2 模块 B：云端视觉分析

云端建议新增独立目录：

- `app/services/visual_analysis/contracts.py`
- `app/services/visual_analysis/analysis.py`
- `app/services/visual_analysis/prompt.py` 或等价职责文件
- 对应工作台路由和自动化测试

如果独立缓存需要数据库持久化，应新增 Alembic 迁移和独立缓存表；不得复用音乐/字幕缓存
记录并造成目录版本变化时全量失效。API 建议为：

```text
POST /api/workbench/visual-analysis
```

必须继续使用当前工作台短期令牌和用户级 Ark 配置。每次请求只分析一条脚本的全部候选；
不得让浏览器直接访问云端，也不得把 Ark Key 下发到本地。

### 20.3 模块 C：工作台视觉状态和时间映射

工作台建议新增：

- `src/jyd_probe/project_visual_analysis.py`
- `src/jyd_probe/semantic_visual_timing.py`
- `src/jyd_probe/semantic_visual_selection.py`
- 对应 `ProjectStore` 快照、接口和测试

视觉状态必须独立保存，不塞进已有音乐/字幕双分支状态。建议快照至少包含：

```json
{
  "snapshot_schema": "jyd.project-visual-analysis.v1",
  "script_sha256": "...",
  "catalog_version": "...",
  "candidate_set_sha256": "...",
  "analysis_status": "SUCCESS",
  "decisions": [],
  "mapping_status": "SUCCESS",
  "suggestions": [],
  "errors": {}
}
```

脚本变化使候选、分析和自动建议失效；音频变化只使时间映射和最终自动建议失效，服务端语义
判断可以复用；目录版本变化重新召回和分析。任何迟到响应都必须通过脚本哈希、候选集合哈希
和目录版本复核，不能覆盖新版本。

### 20.4 模块 D：审核界面和浏览器预览

在新版工作台每条脚本行增加“语义配图”状态入口。MVP 不要求复杂时间线编辑器，但必须能：

- 查看关键词、附近语境、SHOW/REVIEW/SKIP、原因和置信度。
- 预览当前素材。
- 启用、禁用、同概念换图。
- 调整左上/右上、尺寸、开始时间和持续时间。
- 锁定人工修改。
- 单独重试视觉分析。

浏览器播放到贴图时间范围时显示对应预览图；不得另外计算一套时间或位置。

### 20.5 模块 E：4B 剪映成片

扩展当前 4B 冻结配方，使其包含 `visual_overlays`。项目开始渲染后，本次使用的贴图素材、
时间和位置必须冻结，后续目录变化不能静默改变正在生成或已经生成的变体。

底层优先复用 `sticker_apply.add_fullscreen_sticker_to_data()` 已验证的：

- `start_us`
- `duration_us`
- `corner`
- `scale`
- `rotation`
- `opacity`

可以重命名或抽取通用函数，但不得改变旧全屏贴纸和四角贴纸的既有行为。语义贴图使用独立
轨道命名和素材分类。4B 重试只重做本地渲染，不调用 MiniMax、RunningHub 或云端视觉分析。

## 21. 新增接口建议

工作台本地接口建议：

```text
GET  /api/new/semantic-visuals/catalog
GET  /api/new/semantic-visuals/{asset_id}/preview
POST /api/new/projects/{project_id}/visual-analysis
POST /api/new/projects/{project_id}/items/{item_id}/visual-analysis/retry
PUT  /api/new/projects/{project_id}/items/{item_id}/visual-overlays
```

项目级分析请求支持可选 `item_ids`，但工作台内部仍按“一行脚本一次云端请求”执行，项目批量
并发上限沿用内容分析的 10 行或设置更低的独立上限。接口需要保持幂等：相同脚本、相同候选
集合和相同目录版本的普通请求不得重复调用模型。

`PUT visual-overlays` 必须带项目修订号或等价的乐观并发条件，避免浏览器旧页面覆盖较新的
人工修改。

## 22. 必须覆盖的测试矩阵

### 22.1 候选召回

- 最长别名优先、重复词、重叠词、同词多义。
- 换行、空格、全角标点和 Excel 原样脚本字符位置。
- 路径越界、丢失素材、重复 `asset_id`、未知 schema。

### 22.2 云端契约

- SHOW/REVIEW/SKIP 全覆盖。
- 成语、比喻、否定、词语引用、顺带提及和低置信度。
- 未知候选 ID、未知概念 ID、重复/漏返回、越界字符和模型时间字段全部拒绝。
- 缓存命中、强制刷新、部分失败、超时和不同用户隔离。

### 22.3 时间和状态

- 关键词位于单个 cue、跨 cue、重复 cue 和换行附近。
- `raw_cues` 缺失、脚本文本不一致、音频版本变化和封面时间偏移。
- 迟到响应不能覆盖新脚本；人工锁定不能被重分析覆盖。
- 同时最多一张、间隔 6 秒、每分钟最多 5 张和概念 20 秒去重。

### 22.4 预览和成片

- 浏览器与剪映配方逐项一致。
- 左上/右上、缩放、透明度、起止时间和视频尾部裁限。
- 不遮挡底部字幕安全区，不改变主视频和总时长。
- 视觉分支失败、贴图素材丢失或本地渲染失败不会破坏字幕/BGM和已有音视频。

## 23. 分阶段质量门

推荐在一个新任务中按以下检查点推进，每个检查点测试通过后再进入下一步：

1. 契约、目录和候选召回。
2. 云端真实服务边界及 mock API。
3. 本地状态、时间映射和自动筛选。
4. 审核界面和浏览器预览。
5. 剪映配方和成片写入。
6. 跨项目回归、真实 Ark 小样本、Windows 剪映验收。

自动化测试必须 mock Ark、MiniMax、RunningHub 和剪映，不能产生费用。真实 Ark 和剪映验收
必须由用户明确授权；生产部署、生产迁移和默认启用仍是独立步骤。

## 24. 交付时必须回答的问题

新任务交付不能只说“功能已完成”，必须明确：

- 哪些目录概念和素材已经可用。
- 哪些句子会自动显示、待确认或跳过。
- 云端调用次数和缓存键是什么。
- 脚本、音频、目录或人工修改变化时分别会失效什么。
- 浏览器预览与剪映成片是否做过同配方验收。
- 定向测试和两个项目完整回归各自结果。
- 哪些工作只完成本地 mock，哪些经过真实 Ark 或真实剪映。
- 是否部署生产；默认答案应为“没有”，除非用户另行授权。
