# 语音标点停顿配方开发文档

> 创建日期：2026-08-08  
> 当前状态：方案已确认，代码尚未实施  
> 适用项目：`runninghub_mvp` 数字人服务端、`jyd_plain_json_probe` 剪映工作台

## 1. 文档目的

本功能在第一次调用 MiniMax 之前，把用户脚本中的标点和显式停顿要求编译为确定、可审计的
语音停顿配方，降低 MiniMax 偶发重排韵律、跨过逗号断句的概率。目标不是在生成后靠人工
反复试听和付费重试，而是在生成前完成无费用的本地检查、规则编译、版本绑定和防重复校验。

本功能不复用语义配图分析，也不向现有 Ark 内容分析响应增加字段。字幕、语义配图、BGM、
RunningHub、剪映和原始脚本文字继续保持独立。

## 2. 已确认的产品决策

1. 中文逗号、顿号、冒号、分号、句号、问号、感叹号、省略号、破折号和用户显式换行都要
   进入停顿规则，不能只处理某一个示例或某一种标点。
2. 默认规则自动应用于整批脚本，普通用户不需要逐条精调。
3. 用户可在少数特殊位置增加、修改或关闭停顿；人工设置覆盖自动规则，并可锁定。
4. 普通空格不表示停顿。空格可能来自复制、排版或中英文混排，不能成为付费任务的隐式控制符。
5. 页面自动折行不参与停顿；只有脚本文字中真实存在的换行参与。
6. 原始脚本是字幕、字数、内容分析和语义配图的权威文本。MiniMax 专用标记不得写回原文，
   不得出现在字幕、字数统计、搜索、日志或剪映文案中。
7. 规则编译不调用大模型，不增加 Ark 参数、输出长度、费用或失败耦合。
8. 同一份原文、音色、语音参数和停顿配方只能形成一个有效 MiniMax 请求；重复点击或进程
   重启不得重复付费提交。
9. 停顿配方失败时必须在调用 MiniMax 前阻止该行并给出可操作错误，不允许带着未知文本
   降级成付费请求。

## 3. 为什么不能只依赖标点

标点会影响 TTS 韵律，但对生成模型通常是提示而不是逐字执行的硬约束。同一类脚本大多数
可以按逗号自然停顿，少数长句仍可能结合上下文重新组织节奏，例如把：

```text
跟着我，吃对一日三餐健康瘦
```

读成接近“跟着我吃，对一日三餐健康瘦”。这不代表前端或数据库丢失逗号，而是一次生成的
韵律结果偏离作者意图。

MiniMax 官方支持在两个可发音文本之间插入 `<#x#>` 控制语音间隔，`x` 的单位为秒；官方
说明见 [同步语音合成 HTTP](https://platform.minimaxi.com/docs/api-reference/speech-t2a-http)。
项目不让用户直接维护这个服务商标记，而是使用版本化的本地配方，在服务端提交前编译。

## 4. 总体流程

```text
Excel/CSV 或页面脚本
  -> 解析显式停顿语法
  -> 保存未掺入服务商标记的原始脚本
  -> 本地扫描标点和真实换行
  -> 合并自动规则与人工覆盖
  -> 生成并展示预检摘要
  -> 冻结 speech_recipe 与摘要
  -> 数字人服务端严格复核
  -> 编译 MiniMax effective_text
  -> 以完整配方摘要做幂等和缓存判断
  -> 只提交一次 MiniMax
  -> 保存原始 raw_cues、配方版本和音频版本绑定
```

## 5. 职责划分

### 5.1 剪映工作台

- 解析页面和 Excel/CSV 中允许的人工停顿语法。
- 保存原始脚本、规则版本、自动边界、人工覆盖和锁定状态。
- 在产生费用前展示逐行及整批预检摘要。
- 把原始脚本与紧凑配方传给数字人服务端，不直接写 MiniMax `<#x#>`。
- 配方变化时只失效该行当前音频及其后续绑定，历史音频和视频不物理删除。
- 字数统计排除空格、换行和停顿控制语法，只统计实际可朗读内容及正常标点。

### 5.2 数字人服务端

- 严格验证脚本摘要、规则版本、字符边界、时长范围、人工覆盖和额外字段。
- 使用与工作台相同的冻结规则生成权威有效配方；不信任浏览器传入的编译后文本。
- 在调用 MiniMax 前生成 `effective_text`，保存其摘要及配方摘要用于幂等、防重和排障。
- 原始 `speech_script` 始终保持不变；日志只记录长度、摘要、规则版本和边界数量。
- MiniMax 返回后保存 provider 原始 cues，并把音频素材绑定到原始脚本摘要和配方摘要。
- 重试必须显式确认费用；相同有效请求优先复用已有成功结果或正在运行的远程任务。

### 5.3 MiniMax

- 只接收数字人服务端生成的 `effective_text`。
- `<#x#>` 是服务商适配层细节，不进入跨项目公开原文、字幕或视觉契约。

### 5.4 Ark 内容分析与语义配图

- 不新增任何语音停顿字段。
- 继续接收原始脚本；真实换行保留，人工停顿控制语法在调用前移除。
- 失败、重试和缓存均与语音配方独立。

## 6. 默认停顿规则 v1

规则版本冻结为 `jyd.speech-pause-rules.v1`。下表时长表示项目显式注入的最小间隔，不承诺
MiniMax 最终音频的总静音精确等于该数值；模型仍可能为句尾语气增加自然韵律。项目保留
原标点并在其后加入一个显式标记，以保留问句、感叹和收句语气，同时保证边界不会被完全吞掉。

| 输入边界 | 默认显式间隔 | 说明 |
| --- | ---: | --- |
| `、` | 0.10 秒 | 列举短停，避免词组粘连但不切得过碎 |
| `，` | 0.22 秒 | 普通分句的默认最小停顿 |
| `：` | 0.28 秒 | 引出解释、列举或结论 |
| `；` | 0.35 秒 | 比逗号更明显的并列分句 |
| `。` | 0.45 秒 | 保留句号收句语气，再保证句间间隔 |
| `！` | 0.45 秒 | 保留感叹语气 |
| `？` | 0.45 秒 | 保留疑问语气 |
| `……` 或连续 `...` | 0.60 秒 | 犹豫、延迟或强调 |
| `——` | 0.35 秒 | 转折、补充或强调 |
| 单个真实换行 | 0.60 秒 | 段落边界；页面自动折行不算 |
| 一个或多个空白行 | 0.85 秒 | 更强的段落边界，多个空行不继续累加 |

示例：

```text
原始脚本：跟着我，吃对一日三餐健康瘦。
有效文本：跟着我，<#0.22#>吃对一日三餐健康瘦。
```

句尾没有后续可发音文本时不追加标记，因为 MiniMax 要求停顿标记位于两个可发音文本之间。

## 7. 标点扫描和冲突规则

1. 只识别真实文本中的标点，不识别浏览器 CSS 自动折行。
2. 连续标点视为一个边界，使用优先级最高或时长最长的规则，不累计多个时长。
3. 标点后紧接真实换行时，以换行规则为准，不把标点和换行时长相加。
4. 引号、括号和书名号本身不创建停顿；它们只跟随相邻的句读标点。
5. 英文 `, ; : . ! ?` 在确实作为句读时使用对应中文规则，但以下情况不得拆分：
   - 小数和版本号，如 `24.4`、`v2.8`；
   - 时间，如 `8:30`；
   - 千分位，如 `1,000`；
   - URL、邮箱、文件名和已识别缩写。
6. 单个普通半角/全角空格不生成边界，也不转换为 MiniMax 标记。
7. 手动覆盖与自动边界指向同一字符位置时只保留手动值，不叠加。
8. 没有前后可发音文本、越界、重叠、非法小数或未知规则版本时，预检直接失败。

## 8. 手动停顿语法

为兼容 Excel/CSV 和页面直接编辑，提供以下受控语法：

```text
【停】       默认 0.30 秒
【停0.5】   指定 0.50 秒
【不停】     关闭当前位置由相邻标点产生的自动显式停顿
```

产品限制为 0.05～2.00 秒，最多两位小数。虽然 MiniMax 服务商允许更大范围，工作台不开放
会明显破坏口播和视频时长的极端值。

页面应把语法渲染为可点击的停顿标签，而不是要求用户记忆服务商格式：

```text
跟着我， [停顿 0.30 秒] 吃对一日三餐健康瘦
```

保存时执行：

- 从权威原始脚本中移除 `【停…】` 控制语法；
- 以移除后的 Python Unicode code point 位置保存边界；
- 字幕、语义配图、BGM 分析和字数统计只读取移除控制语法后的原始脚本；
- 页面再次编辑时根据配方把边界还原为标签；
- 人工边界默认 `locked=true`，自动重新分析或规则升级不得静默覆盖。

用户也可以完全不输入任何手动标记。默认标点规则必须覆盖普通批量生产场景。

## 9. 真实换行与字符位置

真实换行保留在原始脚本中，因为它同时表达段落结构。字符索引仍按 Python Unicode
code point 的左闭右开规则计算，并包含换行字符；字数展示可以排除换行，但不能为了显示
字数修改权威脚本或后续字符位置。

MiniMax raw cue 可能省略空格和换行。现有字幕映射允许省略这些空白字符，该兼容规则保持
不变。停顿标记由服务端单独保存和过滤，不得混入 raw cue 与原始脚本的字符比较。

## 10. 数据契约建议

跨项目契约建议命名为 `jyd.speech-pause-recipe.v1`：

```json
{
  "schema": "jyd.speech-pause-recipe.v1",
  "rules_version": "jyd.speech-pause-rules.v1",
  "script_sha256": "原始脚本摘要",
  "profile": "balanced",
  "manual_overrides": [
    {
      "char_offset": 291,
      "duration_ms": 300,
      "mode": "force",
      "locked": true
    }
  ]
}
```

`manual_overrides` 只传人工差异，不把每一个自动标点展开到 HTTP 请求中，避免长脚本参数
膨胀。数字人服务端按同一 `rules_version` 重新计算自动边界，得到完整有效配方并严格比对
脚本摘要。`mode` 只允许 `force` 或 `suppress`；`suppress` 时不传 `duration_ms`。

音频 attempt 至少绑定：

- `script_sha256`；
- `pause_recipe_sha256`；
- `rules_version`；
- `effective_text_sha256`；
- 音色身份、语速、音量、音调和模型；
- MiniMax 远程任务 ID、费用确认记录和当前 attempt 版本。

## 11. 生成前预检

预检完全在本地和数字人服务端执行，不调用 Ark、MiniMax、RunningHub 或剪映。

页面整批确认前至少显示：

```text
脚本 14 条 · 实际朗读 8,642 字
自动停顿 386 处 · 人工停顿 2 处 · 关闭自动停顿 1 处
规则：均衡 v1
需要修正：0 条
```

逐行可展开查看原文边界和时长，但默认不要求用户逐个审核。以下情况禁止进入费用确认：

- 控制语法未闭合或时长非法；
- 配方脚本摘要与当前脚本不一致；
- 人工位置越界或落在不可发音边界；
- 同一位置存在冲突的人工设置；
- 工作台与数字人服务端不支持同一规则版本；
- 编译后没有可发音文本或包含未识别的控制标记。

## 12. 幂等、缓存和费用保护

音频请求的有效摘要必须覆盖：

```text
用户 + 原始脚本 + 音色 + 模型 + 语速/音量/音调
+ 规则版本 + profile + 人工覆盖 + effective_text 摘要
```

规则如下：

1. 相同摘要已有成功音频时复用历史素材，不创建 MiniMax 任务。
2. 相同摘要已有远程任务运行时继续轮询原任务，不重复提交。
3. 页面重复点击、HTTP 重试和工作台重启使用同一幂等键。
4. 规则版本或任何人工边界变化都会形成新摘要；再次生成前必须重新确认费用。
5. 自动失败重试不得在提交结果不明确时创建第二个任务。
6. UI 必须明确区分“复用”“生成”“重新生成并计费”。

## 13. raw_cues、字幕与后续视频绑定

- `raw_cues` 永远保存 MiniMax 原始时间轴，不被停顿配方覆盖。
- 原始脚本中的标点继续存在，服务商 `<#x#>` 标记在 cue 入库前过滤。
- 若 MiniMax cue 省略控制标记但保留原标点，沿用现有严格映射。
- 若服务商响应异常包含 `<#x#>`，只允许由当前冻结配方投影并移除；出现未知标记立即把
  字幕映射置为安全降级，不改写原文。
- 音频变化后，4A 基础视频、4B 字幕/BGM/贴图配方和变体按现有版本规则失效或待复核；
  历史素材不删除。
- 后续视频流程读取的是已确认音频和 raw cues，不重新编译或修改语音停顿。

## 14. 状态与失败隔离

建议在工作台逐行增加独立摘要：

```text
NOT_PREPARED -> READY -> FROZEN -> AUDIO_BOUND
             \-> INVALID
```

- `READY`：本地规则和人工语法预检通过。
- `FROZEN`：费用确认时冻结，已经进入音频幂等请求。
- `AUDIO_BOUND`：成功音频绑定同一配方摘要。
- `INVALID`：脚本、规则或人工位置不再匹配，禁止付费提交。

某一行配方无效只阻止该行声音生成，不能清空其他行、已有音频、图片、BGM、字幕、基础视频
或成片。Ark、RunningHub 和剪映状态不参与本状态机。

## 15. 设置和界面

项目默认使用“均衡”规则。第一版可以只公开一个稳定默认值和人工覆盖，避免在没有真实样本
校准前让用户面对过多参数。内部保留 profile 字段，为后续增加“自然 / 均衡 / 清晰”做版本
兼容，但不能在同一规则版本下静默改变数值。

前端至少提供：

- 整批预检摘要；
- 单行“查看停顿”入口；
- 在脚本编辑器中插入默认停顿、指定时长或关闭自动停顿；
- 人工标签的修改、删除和锁定状态；
- 音频生成后显示所用规则版本和停顿数量；
- 重新生成前的费用提示及“为什么需要重做”说明。

## 16. 数据迁移与兼容

- 历史项目没有配方时标记为 `legacy-natural-punctuation`，已有音频继续可用，不回填、不重做。
- 新生成音频默认使用 `jyd.speech-pause-rules.v1`；规则切换只影响新 attempt。
- 数据库只新增列或新表，不重建已有项目、音频任务或父表。
- 工作台与云端版本不匹配时，在任何付费调用前返回稳定错误并提示更新，不能降级成历史自然
  标点模式。
- 更新包继续排除用户 `data`，迁移不得覆盖素材、日志、项目和历史任务。

## 17. 自动化测试

所有第三方必须 mock，不允许真实费用。至少覆盖：

### 17.1 规则单元测试

- 各中文和英文标点的默认边界；
- 连续标点、标点加换行和多个空白行不重复累加；
- 小数、时间、版本号、千分位、URL 和邮箱不误切；
- 普通空格不产生停顿；
- 页面自动折行不进入原始文本；
- 句尾不生成非法 MiniMax 标记；
- Unicode 字符位置、emoji 和中英文混排稳定。

### 17.2 手动语法测试

- `【停】`、`【停0.5】`、`【不停】` 正确提取；
- 非法格式、越界、重复和 0.05～2.00 秒范围；
- 人工覆盖自动边界且不叠加；
- 控制语法不进入字幕、字数、内容分析和视觉分析。

### 17.3 云端契约与费用测试

- 服务端重算自动边界并拒绝未知规则、错误摘要和额外字段；
- 相同请求成功复用、运行中恢复、重复点击不重复提交；
- 配方变化形成新摘要并要求重新确认费用；
- MiniMax 请求包含有效文本，数据库仍保存原始脚本；
- 编译或校验失败时 MiniMax mock 调用次数为 0。

### 17.4 跨项目测试

- 工作台请求可由数字人服务端真实解析器直接消费；
- 返回 raw cues 后仍能绑定原始脚本和配方摘要；
- 空格、换行、标点和手动停顿不会破坏语义字幕映射；
- 音频版本变化按现有规则失效后续配方，但不删除历史素材；
- 全部 mock Ark、MiniMax、RunningHub 和剪映。

## 18. 验收示例

1. “跟着我，吃对一日三餐健康瘦”第一次生成前已经包含明确逗号边界，不依赖生成后补救。
2. “鸡蛋、玉米、红薯，任选一种。”分别生成列举短停、分句停顿和收句间隔。
3. “你吃对了吗？跟着我，一起开始！”保留疑问和感叹语气，同时保证句间不会粘连。
4. `24.4 秒`、`8:30`、`v2.8` 和 `1,000` 不因内部符号产生错误停顿。
5. 用户不做任何人工设置也能批量生成；只在极少数特殊表达中使用 `【停0.5】` 或
   `【不停】`。
6. 相同配置重复点击只产生一个 MiniMax 远程任务；预检失败产生零次付费调用。
7. 字幕、语义配图、BGM 分析和剪映脚本文字始终不包含 `<#x#>` 或 `【停…】`。

## 19. 实施分段

1. 冻结规则、显式语法、解析器和单元测试。
2. 工作台项目数据、预检摘要、编辑器标签和版本失效。
3. 数字人服务端契约、严格复核、MiniMax 编译、幂等与缓存。
4. raw cues 绑定、跨项目测试和历史兼容。
5. 浏览器交互回归、完整 mock 回归、文档同步。
6. 用户明确授权后，以少量真实样本校准默认时长；未授权前不调用真实 MiniMax，不部署生产。

## 20. 当前非目标

- 不让大模型预测每一句停顿。
- 不把语音停顿塞进音乐/字幕内容分析或语义配图契约。
- 不对生成后的音频做自动付费重试。
- 不承诺不同 MiniMax 模型和音色的总静音毫秒完全一致。
- 不自动修改用户原文，不用空格作为隐藏控制符。
- 不部署生产、不修改云端生产账号数据库、不执行真实付费调用。
