# 新版数字人工作台开发顺序

> 创建日期：2026-08-04  
> 适用项目：数字人后端 `runninghub_mvp`、剪映工作台后端 `jyd_plain_json_probe`、新版前端原型 `video_gongyu/video_gongyu`

## 1. 文档目的

本次开发不是建立第三套后端或账号体系，而是把新版页面作为剪映工作台的
`/app/new`，由剪映工作台后端作为统一项目和业务编排入口，继续复用数字人网站账号、
MiniMax、RunningHub 和本地剪映处理能力。

开发采用“薄公共骨架 + 按模块逐个闭环”的方式。每个模块都应完成数据结构、接口、
后端能力、状态与重试、前端接入和自动化测试，再进入下一个模块。不要先写完所有
接口后一次性接前端，也不要让各模块自行定义重复的项目、素材和状态结构。

## 2. 已确认的产品决策

### 2.1 系统边界

```text
浏览器
  -> 剪映工作台后端 :8010
       -> 数字人后端 :8000
            -> MiniMax
            -> RunningHub
       -> 本地剪映处理与导出能力
```

- 浏览器只访问剪映工作台后端，不直接访问数字人后端。
- 普通用户账号只来自数字人网站，工作台不保存普通用户密码。
- 不建立第三套后端、第三套普通账号或新的云端账号数据库。
- 工作台负责统一项目、当前素材版本、跨后端编排和用户可执行操作。
- 数字人后端负责 MiniMax、RunningHub 及其付费任务、状态、重试和原始结果。
- 前端只展示后端状态和调用接口，不能自行决定业务状态。
- 未经用户明确要求，不部署生产环境、不修改云端账号数据库、不自动发布。

### 2.2 用户看到的三类产物

1. 生成音频。
2. 画面合成视频。
3. 变体后的最终视频。

画面合成是一个完整的用户操作阶段，内部流程为：

```text
生成音频 + 图片
  -> RunningHub 数字人任务
  -> 单片段直接使用 / 多片段自动拼接
  -> 根据 MiniMax 时间戳动态预览字幕
  -> 同步预览 BGM
  -> 生成用户可预览的完整画面合成效果
```

画面合成完成后不能自动生成变体，必须等待用户点击页面外部的“生成变体”按钮。

### 2.3 视频预览弹窗

弹窗保留三个按钮：

1. 下载此视频。
2. 下载原始素材。
3. 上传本地视频。

“生成变体”不放进弹窗，由页面外部按钮一次处理当前项目全部符合条件的视频。

- 单片段成功后直接作为后续画面合成的视频源。
- 多片段全部成功后自动拼接，并作为后续画面合成的视频源。
- 所有 RunningHub 原始片段始终保留。
- 上传本地视频时创建新素材版本并切换当前视频，不删除自动生成视频和原始片段。
- 生成变体时冻结提交当时的当前视频版本；运行期间切换当前视频不能改变已提交任务。

### 2.4 字幕第一版原则

- MiniMax 原始时间戳永久保留，不直接覆盖。
- 原始时间戳解决字幕与音频的时间同步；字体、字号和断句属于独立的排版问题。
- 渲染字幕绑定具体音频版本和视频版本。
- BGM 不改变字幕时间轴。
- 第一期固定单行显示；一句过长时优先按标点拆成连续 render cues，拆分后的时间仍严格
  落在原始 cue 时间范围内，原始 MiniMax cues 不修改。
- 单行字幕居中且禁止自动换行，最大宽度为画面 `80%`，字幕距画面底部约 `20%`；使用用户所选真实
  字体文件测量字宽，仍无法可靠排版时标记 `REVIEW_REQUIRED`。
- 用户上传本地视频后，原字幕时间轴保留，但不再自动认定对该视频有效。
- 第一阶段只确定字幕数据契约，不立即实现复杂的自动断句算法。

## 3. 统一职责划分

### 3.1 数字人后端

- 数字人账号验证和用户归属。
- 可用音色、声音克隆、融合和保存。
- MiniMax 音频生成、时间戳、付费保护和失败重试。
- RunningHub 任务创建、轮询、下载和失败重试。
- 原始数字人视频片段及自动拼接源视频。
- 向工作台提供受用户权限和服务权限保护的工作台专用接口。

### 3.2 剪映工作台后端

- `/app/new` 和 `/api/new/*` 的唯一浏览器入口。
- 统一项目编号和用户归属。
- 脚本行、素材版本、当前音频和当前视频。
- 数字人批次、RunningHub 任务和剪映批次之间的关系。
- 跨后端异步操作、状态聚合、失败恢复和可执行操作。
- 字幕排版、BGM、剪映变体和导出。
- 成果库、下载、ZIP 和本地文件生命周期。

### 3.3 新版前端

- 登录、项目输入和数据展示。
- 调用工作台 `/api/new/*` 接口。
- 根据后端返回的 `status` 和 `allowed_actions` 展示按钮。
- 保存未提交的纯 UI 草稿可以使用浏览器状态，但不能把它作为业务事实来源。
- 不保存数字人访问令牌，不直接调用 MiniMax、RunningHub 或数字人后端。

## 4. 公共数据骨架

统一数据以“项目包含多条脚本行”为基础：

```text
Project
  -> ProjectItem（每条脚本）
       -> AudioAsset 版本
       -> OriginalVideoSegment 原始片段
       -> CompositionVideo 画面合成视频版本
       -> UploadedVideo 用户上传视频版本
       -> VariantVideo 变体视频
       -> SubtitleTrack 字幕版本
       -> Operation 异步操作与重试记录
```

建议的核心数据表：

- `projects`：项目 ID、项目编号、账号归属、名称、聚合状态和版本号。
- `project_items`：脚本行 ID、顺序、脚本、图片、音色、当前音频、当前视频和行状态。
- `project_assets`：素材类型、版本、来源、状态、文件或外部引用、创建时间。
- `project_operations`：操作类型、状态、幂等键、尝试次数、错误和结果。
- `project_links`：数字人批次、数字人批次行、RunningHub 子任务和剪映批次关系。

每条脚本行至少保存：

- `current_audio_asset_id`
- `current_video_asset_id`
- 当前字幕版本
- 当前阶段
- 可执行操作

素材更新只切换当前版本指针，不覆盖或静默删除旧版本。

## 5. 模块化实施顺序

## 模块 0：公共项目骨架

### 目标

建立后续所有模块共同使用的最小数据层、权限和接口契约，不调用 MiniMax、RunningHub
或剪映。

### 后端工作

- 为工作台 `control.db` 增加非破坏式数据库升级。
- 建立项目、脚本行、素材、操作和外部批次关联表。
- 所有项目和素材记录绑定数字人 `user_id`。
- 建立后端状态聚合和 `allowed_actions` 计算服务。
- 建立项目编号生成规则，例如 `DH-20260804-0001`。
- 建立字幕占位结构、版本绑定和默认样式策略。

### 第一批接口

```text
POST  /api/new/projects
GET   /api/new/projects
GET   /api/new/projects/{project_id}
PATCH /api/new/projects/{project_id}
PATCH /api/new/projects/{project_id}/items/{item_id}
```

### 验收

- 两个账号不能读取或修改彼此项目。
- 一个项目可以包含多条脚本行。
- 页面需要的状态和按钮权限全部由后端返回。
- 数据库升级保留既有剪映任务、批次和 Agent 数据。
- 进程重启后项目和素材指针不丢失。

## 模块 1：登录与 `/app/new` 外壳

### 后端工作

- 托管新版页面及其静态资源。
- 新增 `/app/new`、新版成果库和声音中心路由。
- 复用现有数字人账号登录和工作台 HTTP-only 会话 Cookie。
- 未登录页面跳转登录，登录后安全返回原地址。

### 前端工作

- `login.html` 替换模拟登录。
- 导航改为工作台路由，不再跳转本地 HTML 文件。
- 接入登录状态、当前用户名和退出接口。

### 验收

- 页面刷新后登录状态仍有效。
- 浏览器看不到数字人访问令牌。
- 账号停用、删除或修改密码后旧会话失效。

## 模块 2：脚本与图片导入

### 后端工作

- Excel/CSV 上传、解析和严格校验。
- 脚本行 ID、内容、顺序和重复检查。
- 图片上传、排序、复用和分配策略。
- 将最终映射保存为 `project_items`，而不是只存在浏览器中。
- 只有允许的项目状态可以修改输入。

### 前端工作

- 替换模拟 Excel 解析。
- 替换浏览器假上传和演示图片映射。
- 表格从项目详情接口渲染。
- 脚本编辑、图片替换和分配策略调用真实接口。

### 验收

- 页面刷新后脚本、图片和顺序保持不变。
- 任一行校验失败时不产生半套业务任务。
- 前端改变显示状态不能绕过后端校验。

## 模块 3：音色与声音生成

### 数字人后端工作

- 提供工作台专用音色列表接口。
- 提供声音克隆、融合、试听和保存接口。
- 提供 MiniMax 音频创建、查询、下载、时间戳和显式重新生成接口。
- 保持现有付费保护、远程任务 ID 持久化和失败恢复规则。

### 工作台后端工作

- 使用当前账号调用数字人后端。
- 项目默认音色原子地应用到全部脚本行，同时保留逐行覆盖接口。
- 创建 `AUDIO_GENERATE` 异步操作。
- 保存数字人音频任务关联和当前音频版本。
- 保存 MiniMax 原始字幕时间戳。
- 支持整项目生成、单行生成和单行重试。
- 音频版本改变后把下游画面合成标记为需要更新，但保留历史产物。

### 前端工作

- 音色列表使用真实数据。
- 项目默认音色控制全部脚本行，逐行下拉框用于单独覆盖。
- 声音克隆中心接入真实接口，按“生成试听、试听、保存、激活”展示完整制作流程。
- 保存后的自定义音色需要显式激活后才能进入核心工作台；音色卡支持二次确认删除，上传
  的本地原始声音样本可在提交前直接试听。
- 接入批量生成、单行重试、试听和下载。
- 显示排队、生成中、成功和失败状态。

### 模块产物

用户看到第一类产物：生成音频。

## 模块 4：画面合成

> 实施时拆为 4A 与 4B。4A 截止到 `base_video`：调用既有 RunningHub 流程、保存所有
> 原始分段、按已确认音频时长规范单/多片段并自动拼接。4B 处理字幕、BGM 和浏览器完整
> 预览配方；普通预览不创建 `composition_video`，明确下载时才按需导出一次。完成 4A
> 不代表模块 4 整体完成，也不得开放或自动触发变体。

### 工作台编排流程

```text
检查脚本行音频和图片
  -> 调用数字人后端创建 RunningHub 批次
  -> 等待各子任务完成
  -> 保存全部原始片段关联
  -> 单片段直接使用 / 多片段自动拼接
  -> 根据 MiniMax 时间戳构造渲染字幕
  -> 添加用户选择的 BGM
  -> 浏览器使用基础视频 + 动态字幕 + BGM 完整预览
  -> 用户明确下载时才调用本地剪映并登记 composition_video
```

### 内部状态

```text
COMPOSITION_QUEUED
DIGITAL_HUMAN_RUNNING
VIDEO_MERGING
BASE_VIDEO_READY
POSTPROCESS_RUNNING
COMPOSITION_READY
COMPOSITION_FAILED
```

### 关键重试边界

- RunningHub 明确失败由数字人后端按现有规则重试。
- RunningHub 已成功但下载失败时只重新下载。
- 自动拼接失败时只重新拼接。
- 字幕或 BGM 失败时只重新生成浏览器预览配方，不能重新调用已成功的付费 RunningHub 任务。
- 普通预览不得控制剪映；下载普通成片时才按需导出一次。
- 网络提交结果不明确时禁止盲目重新提交。
- 完成画面合成后不自动创建变体。

### 字幕第一版

- 保存 MiniMax 原始 cues 和派生的 render cues。
- 多片段在拼接前按对应音频时长规范视频长度，避免字幕偏移逐段累积。
- 字幕样式保存字体、字号和安全宽度；第一期最大行数固定为 1，禁止自动换行。
- 无法可靠排版时返回 `REVIEW_REQUIRED`，不静默生成明显溢出的字幕。

### 模块产物

用户看到第二类产物：包含动态字幕与 BGM 的完整画面合成预览；明确下载时得到普通画面
合成视频。预览本身不要求剪映已启动。

## 模块 5：视频预览和上传替换

### 下载此视频

- 下载脚本行的 `current_video_asset_id`。
- 当前视频可能是自动画面合成版本，也可能是用户上传版本。

### 下载原始素材

- 单片段提供原始 RunningHub 视频。
- 多片段打包全部原始片段，并附带顺序清单。
- 下载不改变项目状态，不删除服务器素材。

### 上传本地视频

- 校验格式、大小和用户权限。
- 创建新视频素材版本。
- 切换 `current_video_asset_id`。
- 保留自动画面合成视频和全部原始片段。
- 将上传文件视为用户已经处理好的完整当前视频。
- 原 MiniMax 字幕继续保留，但不再自动认定对上传视频有效。

### 验收

- 弹窗只保留三个按钮。
- 上传后页面显示新当前视频。
- 历史自动视频仍可从数据和版本记录中恢复。

## 模块 6：批量生成变体

### 工作台后端工作

- 外部按钮一次检查项目所有脚本行。
- 读取并冻结每行当前基础/上传视频版本以及当时的字幕、字体、BGM 预览配方。
- 保存每行变体数量和本次全局变体设置。
- 使用现有剪映排列组合和 Render Job 能力，把视频源、字幕、BGM 与变体效果放入同一任务
  创建剪映批次并一次导出；不得要求先导出普通 `composition_video`。
- 保存项目、脚本行、源视频版本、剪映批次和子任务关系。
- 支持部分成功、失败项重试和“再补 X 个变体”。

### 关键规则

- 任务开始后切换当前视频不改变已提交变体的源视频。
- 用户曾经按需下载普通成片，不代表变体必须以该成片作为中间源；自动基础视频仍按冻结的
  基础视频 + 配方生成变体，避免字幕/BGM 被重复叠加和重复导出。
- 变体失败只重试失败的剪映任务。
- 不能因变体失败重新调用 MiniMax 或 RunningHub。
- 删除一个变体不删除当前视频或其他变体。

### 前端工作

- 替换模拟进度和定时完成。
- 外部按钮展示后端聚合的可执行状态。
- 每行展示实际变体数量、任务进度、失败和补充生成入口。

### 模块产物

用户看到第三类产物：变体后的最终视频。

## 模块 7：成果视频库

> 2026-08-05 已实现：每次变体提交按本机日期和当日全局批次号直接导出到
> `D:\auto\月.日\批次号`，例如 `D:\auto\8.5\1`；项目上传的原始 XLSX/CSV 在剪映
> 任务提交前复制到同一目录。成果库使用数据库中的账号、项目、脚本行、源视频版本和
> 剪映批次索引，并核对该目录中的实际文件，不把裸目录名作为权限依据。

### 后端工作

- 按用户和项目查询最终变体。
- 返回项目编号、脚本行、源视频版本、剪映批次、状态和时间。
- 支持单个下载和批量 ZIP 下载。
- 下载和预览执行用户归属校验。

### 前端工作

- 删除全部写死的演示卡片和模拟下载。
- 按项目、状态和脚本关键词查询真实结果。
- 展示部分失败并允许返回项目重试。

## 模块 8：完整闭环与发布前验证

### 自动化验证

## 6. 素材变化和下游失效规则

| 用户修改 | 保留内容 | 需要重新生成 |
| --- | --- | --- |
| 修改脚本或音色 | 历史音频、视频和变体 | 音频及其后续 |
| 更换图片 | 音频和历史产物 | 画面合成及变体 |
| 修改 BGM 或字幕样式 | 音频、RunningHub 原始片段和历史产物 | 浏览器预览配方及变体；不自动导出普通成片 |
| 上传本地视频 | 所有历史素材 | 新当前视频对应的变体 |
| 修改变体设置 | 当前视频和历史变体 | 新变体批次 |

新版配置表不以“已生成”作为永久只读状态。只要该行当前没有异步任务运行，脚本、音色、
图片、BGM 和字幕样式都可修改；修改后按上表清空当前指针并创建新的下游任务，历史素材、
操作记录和外部任务关联必须保留。全部声音已完成时仍允许用户显式确认费用后再次生成一套
新音频版本。

“需要重新生成”表示后端不再把旧结果标记为当前结果，不表示立即删除旧文件。

## 9. 原计划完成后的新增功能与质量优化（2026-08-05）

本节内容是模块 0～8 原定范围之外的新需求，不回退或重写已经完成的音频切分、并行数字人
生成、封面、字幕、BGM、变体和成果库算法。实现时应另建数据版本与测试，避免把优化误作
原模块缺陷。

### 9.1 智能音乐匹配

- 音乐入库时按固定标签体系保存情绪、场景、能量、节奏、人声、密度、开场方式、循环适配度
  和禁用场景；模型可批量建议标签，但关键结果需要人工复核。
- Excel/CSV 只作为首批标注、审核和导入导出工具；运行时权威数据应按音乐稳定 `identity`
  保存到音乐目录的结构化清单，并带 `taxonomy_version`。
- 云端文本模型把脚本解析为固定结构的 `music_intent`，不得直接根据文件名自由选择音乐。
- 本地工作台根据标签做硬条件过滤、评分、最近使用降权和批次去重，保存最终
  `bgm_identity`、评分理由及模型/标签版本；低置信度时回退到默认音乐或人工选择。
- BGM 在普通画面合成阶段确定；模块 6 冻结并继承已选 BGM，不把背景音乐作为变体维度。

### 9.2 关键词语义前景素材

- 云端内容分析返回 `visual_cues`：原文片段、字符起止位置、标准化 `concept_id`、本地素材
  查询标签、重要度和建议持续时间，不返回本地文件路径。
- MiniMax 返回字词时间戳后，后端把字符位置确定性映射为 `start_us`/`duration_us` 并随项目
  保存；脚本或音频版本变化时旧 cue 失效并重新分析或映射。
- 模块 6 在本地读取 cue，从本地图片库选取素材并放到主视频上层轨道。素材只占据前景或
  局部画面，不替换主轨道、不改变声音与字幕时间轴，也不得早于封面结束时间出现。
- 变体可以改变具体素材、位置、尺寸、进入/退出动画和允许范围内的持续时间；必须避开人物
  面部、主体和底部字幕安全区，并通过稳定随机种子保证可复现和批次内差异。
- 本地关键词词典负责候选召回；云端模型负责语境消歧和重要度判断。云端不可用时允许退化为
  纯词典匹配。音乐意图与 `visual_cues` 可由一次内容分析请求共同返回。

### 9.3 并行数字人片段的接缝优化

- 继续保持“音频先切分 -> 多段音频并行生成多个数字人视频 -> 本地统一拼接”的现有流程。
  禁止把上一段最后一帧作为下一段输入，因为这会把并行任务退化为串行并显著增加总耗时。
- 人物跳变在本地后处理或模块 6 处理，不重新调用 RunningHub。第一版在相邻主视频片段接缝
  添加短视频转场，默认目标为 4～8 帧；不得使用明显闪白，不得改变总音频、字幕时间轴，
  不得把转场扩展到封面之前。
- 转场优先使用短时柔和模糊、轻微推近或极短淡化；长交叉淡化可能产生双脸重影，不能作为
  唯一方案。后续可在本地比较相邻片段边界帧的人脸位置、姿态和亮度，选择跳变更小的切点。
- 接缝附近存在合适 `visual_cue` 时，可让局部前景素材跨越接缝以转移注意力；不存在合适语义
  时只使用通用短转场，不能为了遮挡接缝强行插入无关图片。

### 9.4 新增优化的实施顺序

1. 先实现不改变现有并行生成和时间轴的本地短转场，并回归封面、字幕和 BGM。
2. 定义音乐及前景图片的受控标签体系和本地素材清单。
3. 增加云端内容分析契约，一次返回 `music_intent` 与 `visual_cues`，并完成时间戳映射和版本失效。
4. 在模块 6 接入局部前景素材，验证多变体差异、人物/字幕避让、接缝遮挡和离线降级。
